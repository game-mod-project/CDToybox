# 세션 정리 — 원하는 종을 동반자로 (2026-09-07)

사용자가 원하는 것: **오버레이에서 고른 종을 탈것·특수탈것·반려동물로
등록하고 실제로 데리고/타고 다니는 것.**

아직 안 된다. 다만 막는 지점이 **하나로** 좁혀졌다. 어제 문서
(`2026-09-06-session-close.md`)의 §4 결론은 폐기한다 — 관문은 열려 있다.

---

## 1. 결론부터

동반자를 등록하는 길은 셋이고, **종을 자유롭게 고를 수 있는 것은 하나뿐**이다.

| 경로 | 종 선택 | 조건 |
|---|---|---|
| 2338 `HireMercenaryToTarget` | **자유** | 그 개체가 월드에 실제로 있어야 한다 |
| 2454 `HireMercenaryFromInventory` | 아이템이 결정 | 동행의 부적 6종이 한계 |
| 2386 `CatchBySummon` | 부화체만 | 알 + 둥지 + 5분 |

그래서 남은 문제는 **"원하는 종을 월드에 띄우는 것"** 하나다. 띄우기만
하면 2338 이 등록한다.

---

## 2. 소환 치트 — 벽 넷을 무너뜨렸고 하나 남았다

`SpawnCharacterCheatReq` (**실측 ID 2988**, 처리기 RVA `0x2B6E530`).
앞선 세션이 2510 이라 적어 둔 값으로는 이 처리기가 나오지 않는다.

### 2.1 무너진 것

| 벽 | 실제 |
|---|---|
| 관문이 막고 있다 | **열려 있다.** 검사 함수 `0x35A1E0` 은 `mov al,1; ret` |
| 컨텍스트가 비었다 | 세션 포인터 그대로 살아 있다 |
| 키를 아무거나 넣어도 된다 | 표에 있는 키여야 한다. 없으면 널 문자열을 해시하다 죽는다 |
| 플래그는 아무 값이나 | **종류 코드다. 0 은 유효하지 않다** |
| `B` 인자가 미상 | **한 번도 읽지 않는다.** 진입 시 저장한 자리를 출력 인자로 덮어쓴다 |

플래그(6번째 인자)는 파라미터 객체 `+0xA` 에 그대로 들어간다
(생성자 `0x26CB420`). 이미지에서 그 생성자를 부르는 43곳을 훑으니 쓰이는
값은 `0x0A·0x0D·0x10·0x16·0x1E·0x1F·0x20·0x25·0x27·0x28` 이고 **0 은 한
곳도 없다**. 우리 자리는 `0x28` 을 따로 알아본다(`0x21` 로 바꿔 쓴다).
기본값을 `0x28` 로 두자 크래시가 사라졌다.

### 2.2 남은 하나

플래그를 고친 뒤 처리기는 **끝까지 돈다**.

```
소환 치트 관문: ... -> 열림
소환 만들기: ... -> 값 있음        ; 0x1763570 이 객체를 만들었다
캐릭터 소환 끝 (처리기 경로)        ; 크래시 없음
```

그런데 개체가 월드에 남지 않는다. 화면에도 안 보이고 근처 목록에도 없다.

**다음 한 걸음:** `0x2B6EA68` 의 가상 호출

```
mov  rax, [r12]            ; r12 = 만들어진 객체
lea  r8,  [rsp+0x40]
lea  rdx, [rbp+0x4e8]
mov  rcx, r12
call [rax + 0x88]          ; ← 여기
mov  ebx, [rax]            ; 결과 코드. 0 이면 성공
test ebx, ebx
je   성공 / 아니면 0x3F5 오류
```

이 결과 코드를 읽어야 한다. 가상 호출이라 실행 중에만 대상이 정해지니
`r12` 의 vtable`+0x88` 을 훅에서 찍고, 그 함수를 디스어셈블한다. 소환
쿨타임과 플래그를 찾아낸 것과 같은 방식이다.

## 3. 부적 등록(2454) — 종을 고를 수 없다

실측으로 끝까지 확인했다. 종을 인자로 받지 않는다.

```
[ID 2454][00][본문길이 4][u16 A][u16 B]

A = 컨테이너 종류 (1..21)
    표 0x8752A40 이 A -> A-1 로 옮긴다. 그 표를 열어 읽으니 21행,
    키 1..21, 값 0..20 이 전부다. 캐릭터 키와 무관하다.
    범위 밖이면 코드 0x73353994.
B = 그 컨테이너 안의 슬롯 번호
    조회 0x2078A70 이 [컨테이너] + B * 0xC8 로 슬롯을 집는다.
    슬롯 수를 넘거나 빈 슬롯이면 코드 0x06306EB0.
```

**종은 그 슬롯에 든 아이템이 정한다.** 부적이 6종뿐이니 한계도 6종이다.

거부 코드는 이미지에서 상수 네 곳을 뽑아 프로세스에서 읽어 대조했다.
추측이 아니다.

## 4. 알 부화(2386) — 이름과 다르다

사용자의 실제 절차: **와이번 알 → 둥지에 올리기 → 5분 → 부화 → 획득.**

그때 게임이 보낸 두 메시지의 뜻이 이것으로 확정됐다.

```
2676 아이템 사용 = 알을 둥지에 올린다 (본문의 매번 다른 u64 가 알)
2386 CatchBySummon = 부화한 개체를 거둔다
```

와이어는 머리 5 + 본문 8 이다.

```
52 09 00 08 00 | 01 00 10 A0 | 0D 37 10 B0
                 잡는쪽(둥지)   부화체 액터 핸들
```

첫 필드는 네 표본이 전부 `0xA0100001` 이고, 액터 매니저가 아닌 **별도
매니저**에서 조회된다(`0x2B7CE20`). 우리가 읽는 액터 1718개는 전부
`0xB010` 한 네임스페이스라 거기 없다.

임의의 야생 동물에게 쏘면 아무 일도 일어나지 않는다 — 둥지도 부화체도
없기 때문이다. **야생 개체를 잡는 일반 경로가 아니다.**

## 5. 곁가지로 고친 것

원래 목표와 무관하지만 조사 중에 드러난 기존 결함들이다.

| 결함 | 증상 | 커밋 |
|---|---|---|
| 액터 매니저를 잘못 잡고 영구 고정 | 월드 진입 전에 잡히면 근처 목록이 영영 빔(1703 -> 1) | `758814e` |
| 소환 치트 메시지 ID 가 문서와 다름 | 2510 로는 처리기가 안 나옴. 실측 2988 | `5201a02` |
| 훅 인자 수를 넷으로 선언 | 처리기는 여섯을 받는다. 좌표·플래그가 쓰레기값 | `79bf984` |
| SEH 가 훅 프레임을 건너뛰어 표시가 남음 | 로그 8만 줄(141MB) 폭주 | `47ec251` |

액터 매니저 결함은 **근처 탭 획득 기능에 그대로 있던 버그**다. 지금까지는
순서가 운 좋게 맞았을 뿐이다.

## 6. 넣은 도구

명령 파일(`cdtoybox_cmd.txt`)에 한 줄 쓰면 읽고 지운다.

```
chardump <이름조각> [개수]   캐릭터 표에서 키를 찾는다
actordump [이름조각] [개수]  살아 있는 액터를 찾는다
actordiff                    두 번 불러 그 사이 생기고 사라진 액터를 낸다
unlock                       크래시로 잠긴 세션을 손으로 푼다
hireitem <A> [B]             2454 를 직접 구동한다
catch <대상핸들> [잡는쪽]    2386 을 직접 구동한다
spawnchar <캐릭터키> [B] [플래그]  2988 (플래그 기본값 0x28)
```

`actordiff` 가 필요했던 이유: 액터 총수는 살아 있는 월드에서 ±1 이 잡음과
구별되지 않는다(1703 -> 1704 -> 1703 을 실제로 봤다).

오버레이에는 **동반자 아이템 탭**을 넣었다. 부적·알을 버튼 하나로
지급하고, 줄마다 실측/미확인을 표시한다.

## 7. 교훈

**하나. 목적을 확인하고 시작할 것.**
"오버레이에서 추가할 수 있는지 검토"라는 한 줄에서 목적을 멋대로 채워
넣고 알 지급·둥지 관측까지 갔다. 사용자가 "그 절차를 건너뛰려고 만드는
기능인데 왜 절차를 관측하나"라고 짚어 주고서야 방향이 잡혔다.

**둘. 상수는 읽어서 대조할 것.**
거부 코드가 어느 갈림길인지는 이미지에서 상수를 뽑아 프로세스에서 읽으면
확정된다. 오늘 그 방법으로 두 번 판정했고 두 번 다 추측과 달랐다.

**셋. 표는 열어 볼 것.**
"A 가 캐릭터 키로 보인다"고 커밋까지 했는데, 표를 열어 보니 1..21 을
0..20 으로 옮기는 표였다. 여는 데 10분이 안 걸렸다.

**넷. 이름을 믿지 말 것.**
`CatchBySummon` 은 붙잡기가 아니라 부화체 거두기였다. 이름으로 세운 가설
위에 기능과 시험까지 쌓았다가 되돌렸다.
