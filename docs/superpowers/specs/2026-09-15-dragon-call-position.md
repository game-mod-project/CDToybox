# 드래곤 "호출할 수 없는 위치" — 배제한 것과 다음 한 걸음 (2026-09-15)

A.T.A.G. 는 휠 소환·탑승·파트 장착까지 **전부 된다**. 같은 처리를 받은 블랙스타만
`호출할 수 없는 위치입니다` 로 막힌다. 이 문서는 **무엇이 범인이 아닌지**를
실측으로 못박아, 다음 세션이 같은 땅을 다시 파지 않게 한다.

## 0. 한 줄

**장소 관련 정적 데이터는 다 소진했다.** 거부는 요청을 조립하기도 전에 클라이언트
안에서 끝나므로, 다음은 정적 표가 아니라 **조건 객체**를 봐야 한다.

## 1. 확정된 사실

### 1-1. 게이트 `0x2ACA250` 은 진짜 경로 위에 있다 (앞선 기록 정정)

`summon-wheel-real-path` 메모와 앞선 스펙이 "게이트는 무효 경로(2962 서버 메시지
에서만 불린다)" 라고 닫아 두었는데 **틀렸다.** 호출자를 디스어셈블하면 계약이
그대로 보인다:

```
0x2ADBB96  movzx r9d, bx        ; r9 = 동반자 카테고리 (우리 로그의 "키=0x5")
0x2ADBB9A  mov   r8, rdi
0x2ADBB9D  lea   rdx, [rbp+0xc70]
0x2ADBBA4  call  0x2ACA250      ; 게이트
0x2ADBBA9  mov   eax, [rax]     ; 반환 포인터의 첫 dword = **오류 코드**
0x2ADBBAB  test  eax, eax
0x2ADBBAD  je    0x2ADBBE7      ; 0 이면 계속 = 성공
0x2ADBBAF  mov   [rsi], eax     ; 아니면 오류 코드를 내보내고 빠져나감
```

A.T.A.G. 소환이 `키=0x5 결과=0` 으로 지나갔고 **1초 뒤 월드에 나왔다**(실측
19:51:28→29). `결과=0` 은 "안 됐다" 가 아니라 "오류 없음" 이었다.

### 1-2. 드래곤은 그 게이트에 닿지도 않는다

드래곤을 누른 시각 전후로 **우리 훅이 하나도 안 찍힌다** - 동반자 캡처 11경로 ·
게이트 `0x2ACA250` · 스폰 `0x2A22DE0` · 알림 `0xFB7F060`(msg 0x3F5) 전부 조용하다.
즉 거부는 **요청 조립 이전, 클라이언트 자체 판정**이다. 토스트도 그 판정이 낸다.

## 3. 다음 한 걸음 — 조건 객체

실행 파일 문자열에서 나온 이름들이 방향을 준다:

```
AICondition_CheckCallVehicleSpawnVoxelType      ← 복셀 검사가 **조건 클래스**다
ConditionData_CheckMercenaryCallCooltime
ConditionData_GetFactionResearchProgress
eErrNoCallVehicleInvalidPosition                eErrNoCallVehicleInvalidPosition_sequencerEvade
eErrNoInvalidCallMercenarySpawnPositionType     eErrNoCallVehicleMercenaryMovableNavigation

```

즉 복셀 검사는 `CharacterInfo` 를 직접 읽는 코드가 아니라 **`AICondition_*` 객체**로
되어 있다. 우리가 `CharacterInfo` 쪽 개수를 0 으로 만들어도, 조건 객체가 자기
설정값을 들고 있으면 그대로 돈다 - 관측 결과와 정확히 맞는다.

이 모드는 이미 **`ConditionInfoManager`(RVA `0x06C2F260`)** 를 읽는다
(`reserveslot.h` - 예약 슬롯의 원소마다 `{u16 SpecialName, u16 ConditionInfoKey}`).
`gamedata/conditioninfo` 표도 꺼내 놨다(1.8MB).

**권하는 순서**

1. RTTI 로 `AICondition_CheckCallVehicleSpawnVoxelType` 인스턴스를 찾아 배치를 본다
   (probe `objects` / `instances`). 설정된 복셀 타입이 보이면 그게 답이다.
2. 그 클래스의 vtable 평가 함수에 훅을 걸어 **드래곤을 누를 때 불리는지**, 인자와
   결과가 무엇인지 찍는다. 지금 우리 훅은 이 층을 아예 안 보고 있다.
3. 안 불리면 `eErrNoInvalidCallMercenarySpawnPositionType` 등 오류 이름값을 찾아
   그 상수를 쓰는 코드로 거슬러 올라간다.

## 4. 곁들여 확정된 것

- A.T.A.G. 재소환 쿨다운은 **60분**(`_callMercenaryCoolTime` 3600초), 탑승 제한 10분.
  드래곤도 같다.
- **"소환 쿨다운 풀기" 는 이미 돌기 시작한 대기에 안 듣는다.** 정적 값을 1초로
  바꿔 둔 상태에서도 42분이 그대로 돌았다. 마감 시각을 부를 때 따로 박아 둔다.
  그 자리는 명부 레코드가 아니다(§2 마지막 줄).
- 게임 자신의 감소 아이템이 넷 있다 - `1002632`/`1003773`(A.T.A.G. I·II) ·
  `1002631`/`1003772`(드래곤 I·II). 하나당 5~10분. 오버레이에 지급 버튼을 뒀다.
- 우리 `useitem`(2976 구동)으로는 **대기 시간이 안 줄었다**(48분→42분, 경과 시간과
  같다). 사용은 가방에서 해야 한다.

## 6. 경로를 끝까지 따라갔다 (2026-09-15 밤, 진단 v8)

훅 자리를 `.pdata` 로 확정한 뒤에야 제대로 찍혔다. **앞서 "드래곤 클릭은 아무
데도 안 간다" 고 적은 것은 틀렸다** - 엉뚱한 주소에 걸린 훅의 "0건" 을 관측으로
읽은 것이었다.

실측(21:41:28, 드래곤 클릭):

```
휠함수 진입(0x29411E0): 호출자=+0x26B29F4
휠소환 진입(0x2B78330): 호출자=+0x2941355
스폰0x2A22DE0[0]:      호출자=+0x2B78493  r8=1000006  결과물=0x0
```

사슬이 끝까지 이어진다. 반면 A.T.A.G. 는 **다른 길**로 간다 - `소환게이트 키=0x5
오류코드=0`(21:42:02) 직후 21:42:04 에 월드에 나왔고, 스폰 프리미티브를 안 거친다.

### 6-1. `0x2A22DE0` 은 스폰 프리미티브가 아니라 예약 슬롯 조회다

앞선 기록이 이 함수를 "스폰 프리미티브" 라 불렀는데, 디스어셈블하면 **슬롯 키
해시 조회**다. 배치를 전부 풀었다(실측값은 세션마다 다르다):

```
r11 = [이미지+0x6C2E300]        ReserveSlotInfoManager
  +0x08  개수 28
  +0x68  버킷 수 (실측 2)      <- `div ecx` 의 제수
  +0x6C  28                    <- 0 이면 즉시 실패
  +0x78  버킷 표                버킷 = 키 % 버킷수, 크기 0x100
           [0] 항목 수 · +8 부터 {u32 키, u32 슬롯색인} × n
  +0x80  슬롯 배열              레코드 = [배열 + 색인*8]
슬롯 레코드  +0x00 ? · +0x04 키 · +0x08 u16(**0xFFFF 면 실패 경로**)
```

실측: 버킷0 에 15항목, 키 1000006 -> 색인 24 · 키 1000020 -> 색인 26.
레코드 `+0x08` 은 각각 **24 · 26** 으로 **0xFFFF 가 아니다** — 즉 **조회도, 그
다음 관문도 드래곤에서 통과한다.**

### 6-2. 우리가 찍던 "결과물" 의 정체

```
0x2A22F2B  r9  = rbp+0x170
0x2A22F32  r8d = di            <- 슬롯 레코드 +0x08 의 u16
0x2A22F36  rdx = rbp+0x4C0
0x2A22F3D  rcx = r14
0x2A22F40  call 0x20170E0      <- **진짜 일꾼**
0x2A22F4B  mov [rsi], eax      <- 우리가 out 에서 읽던 값 = 그 반환값
```

즉 `결과물` 은 **`0x20170E0` 의 반환값**이다. 실패 경로(0x2A22E6A)는 전역
`[0x6BA0F60]` 을 대신 쓴다.

관측: 드래곤은 **늘 0**. A.T.A.G. 는 **0이 아닌 값을 받은 적이 있다**
(20:35:48, `r8=1000019 결과 4205559856`). 0/비0 이 갈림이다.

### 6-3. 다음 한 걸음

**갈리는 자리는 `0x20170E0` 안이다.** 인자는 위 넷이고, 드래곤에서 0을 낸다.
거기에 훅을 걸어 인자와 반환을 찍거나, 함수를 디스어셈블해 0을 내는 분기를
찾는다. 이제 범위가 함수 하나다.

**주의**: 훅 자리는 반드시 `tools/rtti/funcstart.py` 로 확정한다. 패딩 어림짐작은
셋 중 둘을 틀렸고, 함수 중간에 건 훅은 게임을 팅기게 할 수 있다.

## 7. `0x20170E0` 을 끝까지 읽었다 (2026-09-16 아침)

`.pdata` 로 잡은 함수 범위는 **0x20170E0 ~ 0x20175DC (1276바이트)** 이고, 끝의
32바이트는 코드가 아니라 **8칸짜리 점프표**(0x20175BC)다.

### 7-1. 구조

```
r14 = [arg1+8] · rsi = arg2(오류버퍼) · ebx = arg3(슬롯색인 u16) · rdi = arg4
0x201710D  0x200BDC0(arg4)  -> 참이면 곧장 성공
0x2017116  rax = 0x382A30(&슬롯색인)      <- 슬롯 정보 레코드
           [rax+0x80] != 0 이면 -> [rdi+0xEC] != 0xFFFF 만 보고 성공
           [rax+0x80] == 0 이면 -> **[rax+0x41] (0..7) 로 8갈래 분기**
```

여덟 갈래는 전부 같은 꼴이다 — `rdi` 는 **배타적 합집합**이라, 자기 갈래가
쓰는 칸만 채워져 있고 나머지(`+0xC8`·`+0xCA`·`+0xD8`·`+0xDC`·`+0xE0`·`+0xE8`)
는 비어(0xFFFF 또는 0) 있어야 한다. 아니면 범용 거부다.

| 점프표 | 진입 | 쓰는 칸 | 조회 대상 |
|---|---|---|---|
| 0 | 0x2017188 | +0xC8/+0xCA | 0x2074BA0 → 0x2079F00 |
| 1 | 0x2017256 | +0xDC | 관리자 `[0x6C2E330]` |
| 2 | 0x20172ED | +0xE0 | 관리자 `[0x6C2E328]` |
| 3 | 0x20173CE | +0xE8 | 0x382D80 |
| 4 | 0x2017448 | +0xCC | 0x384D50 |
| 5 | 0x201746D | +0xEA | 0x3830B0 → 0x17B1850 |
| 6 | 0x2017436 | +0x100 | 0 이 아니기만 하면 된다 |
| 7 | 0x201749D | **+0xD8** | 슬롯의 `+0x58` 목록(개수 `+0x60`) |

**갈래 7 이 동반자 갈래다.** `[rdi+0xD8]`(카테고리)가 슬롯이 허용하는 u16
목록에 있어야 하고 — 이것이 "메인 휠은 1·5 만 받는다" 의 실체다 — 그 뒤
`[r14+0xA0]` · `[…+0xD0]` 가 살아 있어야 하며, 마지막으로
`0x2096C30(…, 카테고리, u16)` 의 결과가 `+0x28 != -1` 이고 `+0x20 != 0xFFFF`
여야 한다(= 그 칸에 등록된 동반자가 있어야 한다).

### 7-2. 거부 코드 여덟 개를 실측했다

전역들은 파일에 없는 `.bss` 라 정적으로는 못 읽는다. 실행 중 게임에서 읽었다:

| 기록 자리 | 전역 | 코드 | 조건 |
|---|---|---|---|
| 0x201713E | — | **0** | 성공 |
| 0x20171B0 | 0x6BBBC08 | 4257992575 | 갈래0: 0x2074BA0 이 널 |
| 0x2017235 · 0x20172E6 · 0x20173AE | 0x6BBCA10 | 3825518385 | **범용 거부** |
| 0x2017242 | 0x6BBCDE4 | 103837360 | 갈래0: 조회 결과가 비었다 |
| 0x20174DA | 0x6BBC014 | 1172209432 | 갈래7: `+0xD8` 이 0xFFFF |
| 0x2017516 | 0x6BBC0C0 | 300143221 | 갈래7: 카테고리가 슬롯 목록 밖 |
| 0x201752F | 0x6BBC24C | 2542652655 | 갈래7: `[r14+0xA0]` 널 |
| 0x2017548 | 0x6BAA568 | 1773986448 | 갈래7: `[…+0xD0]` 널 |
| 0x20175A7 | 0x6BBC008 | 4205559856 | 갈래7: 등록된 동반자 없음 |

### 7-3. **앞 기록을 뒤집는다 — 드래곤은 이 관문을 통과한다**

§6-2 에서 "결과물 = 반환된 포인터의 하위 32비트" 라고 적었다. **틀렸다.**
바깥 함수는 포인터를 역참조한다:

```
0x2A22F40  call 0x20170E0
0x2A22F45  mov  eax, [rax]     <- 역참조
0x2A22F47  test eax, eax
0x2A22F49  je   성공경로
0x2A22F4B  mov  [rsi], eax     <- 비0 일 때만 바깥 버퍼로
```

근거는 두 가지다. 하나, 명령 자체. 둘, A.T.A.G. 가 20:35:48 에 받은
`4205559856` 이 위 표의 0x6BBC008 과 **정확히 일치**한다 — 스택 포인터의
하위 32비트가 오류 전역과 같을 수는 없다.

따라서 **드래곤의 `결과물=0x0` 은 "통과" 였다.**

### 7-4. 그러면 메시지는 어디서 나오는가

휠 소환 루틴의 꼬리를 읽으면 답이 반쯤 나온다:

```
0x2B7849E  ebx = [rbp+0xA8]          <- 0x2A22DE0 이 남긴 오류 코드
0x2B784A4  test ebx, ebx
0x2B784A6  je  -> 조용히 반환          <- **0 이면 토스트가 없다**
0x2B784AC  esi = 0x3F5 (알림 번호)
           페이로드 17바이트 = {u16 0x3F5, u8 0xFF, **u32 오류코드**, u16, u64}
0x2B78547  call 0x26B14E0
```

즉 코드가 0 이면 "호출할 수 없는 위치입니다" 가 **뜰 수 없다**. 그런데 떴다.
남은 갈래는 둘이다.

1. 같은 꼴의 휠 루틴이 여럿이다(0x2B78181·0x2B7801F·0x2B77E82 … 전부 0x3F5 을
   쓴다). 드래곤은 우리가 후킹한 0x2B78330 이 아닌 다른 루틴을 탄다.
2. 요청은 실제로 나갔고, 거부는 **응답을 받은 뒤** 뜬다.

v9 진단이 `0x20170E0` 을 **호출자 RVA 와 함께** 전부 찍으므로, 드래곤을 한 번
누르면 1번인지 2번인지가 그 자리에서 갈린다.

**주의**: 알림 송신 `0x26B14E0` 은 `0xFB7F060` 으로 가는 점프 썽크다 — 게임을
팅기게 했던 바로 그 함수다. 여기에는 다시 훅을 걸지 않는다.

## 8. 거부의 정체 - "휠 칸에 안 올려놨다" (2026-09-16, 실측으로 종결)

드래곤 클릭의 거부 코드는 **4205559856 (0xFAABC030)** 이었다. §7 표의
`0x20175A7`, 갈래 7 의 마지막 관문이다. 같은 로그에서 말(카테고리 1)은
`코드=0` 으로 나란히 찍혔다 - **카테고리 관문은 통과**한다.

`0x2096C30` 을 후킹해 목록을 통째로 찍으니 답이 그대로 나왔다:

```
카테고리=1 -> 찾음 (+0x20=4100  +0x28=1000109)   말
카테고리=3 -> 찾음 (+0x20=6818  +0x28=1000602)   A.T.A.G.
카테고리=2 -> 빈손 (+0x20=65535 +0x28=-1)        드래곤
  카테고리 2 레코드 - 항목 2개 · 둘 다 칸=65535
```

항목 하나가 곧 **동반자 하나**이고, 배치는:

| 칸 | 뜻 |
|---|---|
| +0x20 | u16 종행 |
| +0x28 | i64 동반자 번호 |
| +0x148 | u16 **올려 둔 휠 칸** (0xFFFF = 안 올려놨다) |

드래곤 항목은 비어 있지 않았다 - **종행 7008 · 번호 1000483 / 1000724** 로
멀쩡히 있었고, `+0x148` 만 0xFFFF 였다. 즉 **잠긴 게 아니라 휠 칸에 안 올라가
있었다.** 실행 중 게임에서 그 두 바이트를 0 으로 쓰자 거부가 사라졌다
(사용자 실측: "아무것도 안 뜸").

### 8-1. 빈 칸을 다 채우면 안 된다

말 카테고리에도 `+0x148 = 0xFFFF` 인 항목이 다섯이고, 전부 진짜 동반자다
(종행 4073·4075·3643·3753·**6679 프라이든** - 명부에 있는 말이다). 가진 것을
다 휠에 올려놓지는 않기 때문이다. 그래서 채울 때는 **종행을 못 박는다**.

### 8-2. 얹기는 두 가지를 같이 하고 있었다

얹기는 카테고리만 바꾸는 게 아니라 **장소 제한도 함께 풀고** 있었다:

```
종행 7008 호출 지형 요구 1개 -> 0 · 지면 거리 30 -> 0 · 탈출로 그룹 2 -> 5
```

그런데 얹기를 켜면 카테고리가 5 로 가서 **카테고리 2 에 채운 등록이 안 닿고**,
끄면 등록은 닿지만 **장소 제한이 도로 조여진다**. 그래서 둘을 갈랐다:

- `wheel_fill` - 고른 종의 `+0x148` 을 채운다(`0x2096C30` 훅이 쓴다)
- `wheel_swap_slot` - 끄면 장소 제한만 풀고 칸은 제자리에 둔다

드래곤은 **제 칸(7시, 예약 슬롯 1000020)** 이 원래 카테고리 2 를 받으므로,
등록을 채운 뒤에는 옮길 이유가 없다.

## 9. 클라이언트로는 여기가 끝이다 (2026-09-16, 종결)

거부 메시지는 **없앴다**. §8 의 등록(`+0x148`)을 채우자 "호출할 수 없는
위치입니다" 가 사라졌고, 그 쓰기는 **세이브에 남아** 재시작 세 번을 넘겼다
(10:17:51 `카테고리=2 … 찾음 (+0x20=7008 +0x28=1000483)`).

그런데 **드래곤은 여전히 월드에 안 나온다.** 그래서 A.T.A.G.(나온다)와 같은
자로 끝까지 쟀다.

### 9-1. 마지막 비교

`0x2A22DE0` 의 꼬리는 분기가 없다 - 일은 전부 `0x292B040` 이 한다. 그 호출을
후킹해 인자 여섯과 반환, 그리고 **출력 버퍼 둘**까지 읽었다:

| | 반환 | `[a5]` | `[a6]` |
|---|---|---|---|
| A.T.A.G. (슬롯키 1000019) | `0xF4240` | …`19` | **0** |
| 드래곤 (슬롯키 1000020) | `0xF4240` | …`1A` | **0** |

`[a5]` 의 `0x19`/`0x1A` 는 슬롯 번호(25·26) 그 자체다. **다른 것이 없다.**

### 9-2. 통과한 관문 전부

카테고리 · 예약 슬롯 조회 · 거부 코드 판정(갈래 7 전부) · 등록 목록 ·
호출 지형 요구 · 지면 거리 · 탈출로 그룹 · 최대 고도 · 복셀 타입 ·
소환 배달부와 그 출력 버퍼 둘.

**드래곤은 이 모두를 A.T.A.G. 와 똑같이 통과한다.** 그런데 A.T.A.G. 만 나온다.

### 9-3. 결론

실제 스폰은 클라이언트가 결정하지 않는다. 클라이언트는 요청까지만 하고, 그
뒤는 서버가 내준다 - 그리고 서버가 이 계정에 드래곤을 안 내준다. **모드로
뚫을 수 있는 자리가 아니다.**

앞선 세션들의 "서버 주도 구조 벽" 은 **A.T.A.G. 에 대해서는 틀렸고**(벽은
동반자 카테고리 한 칸이었다) **드래곤에 대해서는 맞았다.** 둘을 한 덩어리로
묶어 닫은 것이 잘못이었지, 서버 판단 자체가 틀린 건 아니었다.

### 9-4. 다시 판다면

여기서 더 가려면 클라 안이 아니라 **주고받는 메시지**를 봐야 한다. 지금까지
쓴 훅은 전부 소환 요청 *조립* 단계이고, 응답 처리 쪽은 한 번도 안 봤다.
`동반자 캡처` 의 11경로는 휠 소환을 안 덮는다(말이 나올 때도 안 찍힌다).
