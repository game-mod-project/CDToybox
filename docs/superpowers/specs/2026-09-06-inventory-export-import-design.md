# 인벤토리 Export / Import 설계 (담금질·연마·소켓 보석 완전 복원)

> **정리 (2026-09-21) — 🗑 폐기.** 여기서 설계한 export/import 기능은 2026-09-06
> 제거됐고 다시 만들지 않았다(지금 코드에 없다). 설계의 전제였던 소켓 벽 둘은 이후
> 없어졌다 — 아래 "⚠️ 정정 (2026-09-07 · 2026-09-08)".

## 배경 / 목표

예전 export/import 는 **아이템 종류만** 확인하고 import 를 **신규 지급**으로 처리해,
소켓·언락 상태가 날아가고 지급 경로 소켓은 게임이 막아(2026-09-04) 크래시했다.

이번 목표: 인벤토리를 **통째로 export** 하고, import 에서 **기존 아이템을 제자리
복원**해 담금질·연마·**이미 열린 소켓의 박힌 보석**까지 되살린다.

## 인벤토리 레코드 오프셋 (실측, inventory.cpp)

```
컴포넌트 +0x18 컨테이너 포인터 배열, +0x20 개수
컨테이너 +0x00 레코드배열, +0x08 칸수, +0x10 종류(u16), +0x12 사용, +0x14 용량
레코드   0xC8 간격
  +0x00 u64 인스턴스 ID (세션마다·리로드마다 바뀔 수 있음 - 키 아님)
  +0x08 u16 순번(아이템 표 인덱스)    +0x0A u16 담금질
  +0x10 i64 수량
  +0x40 u16 현재 내구도 (0xFFFF=내구도 없음)
  +0x58 u16 연마
  +0x60 ptr 소켓 벡터  +0x68 u32 소켓 칸수(실측 5)
소켓 6바이트/칸 sp+k*6:
  +0 u16 보석 순번  +2 u16 마커(채움=0xFFFF)  +4 u8 인덱스(열림=k, 잠김=0xFF)  +5 상태
```

## Export 파일 형식 (텍스트, 기존 stash 형식 확장)

한 줄 = 한 아이템. 컨테이너 종류별로 묶는다.
```
# CDToybox inventory export v2
[container kind=1]
순번=6283 qty=1 temper=0 sharp=100 dur=30 sockets=3318:0,FFFF:1,FFFF:2,-:3,-:4
...
```
- `sockets` 는 칸별 `보석순번:인덱스`. 빈 열린칸 `FFFF:k`, 잠긴칸 `-:k`(정보만, import 시 스킵).
- 인스턴스 ID 는 **저장 안 함**(리로드마다 바뀜). 매칭은 순번+슬롯 위치+담금질 등
  조합, 또는 "지급 후 복원" 방식(아래).

## Import 전략 (핵심 결정)

두 경우로 나뉜다:

### A. 이미 인벤토리에 있는 아이템 복원 (제자리)
- 순번으로 현재 인벤토리 레코드를 매칭(동일 순번 여러 개면 슬롯 순서/기존값으로).
- 담금질(+0x0A)·연마(+0x58)를 제자리 쓰기.
- **열린 소켓**(인덱스≠0xFF)에만 보석(+0,+2) 제자리 쓰기. **잠긴 칸은 스킵**.
- 단일 쓰기(both-realms 불필요, 저장 생존 확정).

### B. 없는 아이템 (신규 지급)
- grant 경로로 지급 + 담금질·연마 세팅(지급이 지원).
- **소켓은 못 넣음**(지급 경로 죽음). 지급 후 그 아이템이 **이미 열린 소켓을
  가지고 생성되면** A 로 넘어가 보석을 채운다(아이템 정의가 기본 열린 소켓을
  주는 경우만). 대개 어비스 기어는 잠긴 채 지급되므로 소켓 복원은 A 대상에 한정.

### 착용 장비
- import 시 착용 중인 것은 equip 에디터 경로(both-realms + 재장착)로 복원.
- 또는 "인벤토리로 내린 뒤 복원 후 재장착" 안내.

  **"게임이 검증한다" 는 추측이었고 틀렸다** — 검증이 없다(2026-09-08 실측).
  다만 이 문서의 import 는 **복원**이 목적이므로 잠긴 칸을 건드리지 않는
  규칙 자체는 그대로 두는 편이 맞다. 여는 것은 별도 기능이다.
- 소켓 벡터 포인터·칸수(+0x68≤8) 검증 후에만 쓴다. 칸수 이상하면 그 레코드 스킵.
- 컨테이너 확장 필드(+0x14 등)는 **건드리지 않는다**(가방 크래시 전례).
- 쓰기 전 순번이 실제 아이템 표에 있는지, 보석 순번이 소켓 보석(분류 74)인지 검증.
- 첫 사용은 **버릴 세이브** 권장(문구 표시).

## 코드 계획

- `game/inv_io.{h,cpp}`: `inventory_export(reader, path)`,
  `inventory_import(reader, path, ImportResult*)`.
  - export: discover_inventory → 컨테이너/레코드/소켓 읽어 파일로.
  - import: 파일 파싱 → 매칭 → 제자리 쓰기(SEH). grant 필요분은 큐로 grant 경로에.
- 쓰기 헬퍼는 equip.cpp 의 wr16 패턴 재사용(인프로세스 SEH).
- UI: 인벤토리 패널에 "내보내기 / 가져오기" 버튼(+ 경로/파일 선택은 고정 경로로 시작).
- probe: invsock(열린 소켓 덤프)·poke(WriteProcessMemory)·aob 는 이미 추가됨(진단).
