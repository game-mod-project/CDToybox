-> develop, 커밋 `17c325d` … `3ae3964`.

## 요약

**원인은 게이트가 아니라 세션 표였다.** 표(16칸)에 축출이 없어, 월드에 한 번
들어가면 칸이 다 차고 그 뒤에 생긴 세션은 조용히 버려졌다. 인플레이스 저장/
로드가 만든 **살아 있는 세션이 표에 아예 못 들어와**, 어떤 기준으로 골라도
고를 수가 없었다. 표에 축출을 넣고(F2) 쓰레기 칸을 막자(F1) 증상이 사라졌다.

## 왜 세 번의 수정이 모두 빗나갔나

지금까지 고른 방법만 세 번 바꿨다.

| 시도 | 기준 | 왜 깨졌나 |
| --- | --- | --- |
| 처음 | 서버 + 호출 최다(`best_actor_index`) | 옛 세션이 누적 1위로 남아 죽은 포인터를 뽑았다 |
| 2026-09-06 | + freshness(`best_live_session_index`) | 로드 뒤엔 **표 전체가 똑같이 오래돼** '가장 최근 것 대비' 비교가 무의미해졌다 |
| 2026-09-07 | 서버 + 게이트(`gate_object`) | 게이트가 열리는 세션이 **표에 없어** "세션 못 찾음" |

셋 다 **표 안에서 고르는** 문제였다. 표가 틀렸다는 것은 표를 볼 수 없어 아무도
몰랐다 - 이 표는 훅이 모으는 모드 안쪽 값이라 `cdtb_probe` 로도 안 보인다.

## 계측: `sessions` 명령 (커밋 `17c325d`)

명령 파일(`bin64/cdtoybox_cmd.txt`)에 `sessions` 한 줄을 넣으면
`CDToybox.log` 에 표 전체가 찍힌다. 아무것도 구동하지 않고, 읽기는 전부
안전 읽기(SEH)라 풀린 세션을 만나도 실패로 돌아온다.

```
세션표 11/16
  [0] 0x399160E0200 서버 호출 13792 마지막 3766ms 전 게이트 열림 0x39916030080
      생존 예 액터 0x3991619A280 ServerInventoryActorComponent
  ...
  선택 지금 규칙(서버+게이트): [13] 0x399160E0D00
  선택 옛 기준·참고(서버+호출최다): [0] 0x399160E0200
  선택 옛 기준·참고(서버+freshness): [13] 0x399160E0D00
```

머리의 `n/16` 이 포화를 보여 준다. 옛 기준 두 줄은 참고로 남겼다 - 로드 뒤
그것들이 죽은 세션을 잡는 모습이 나란히 보이는 것이 이 진단의 쓸모다.

## 실측 (수정 전)

### 로드 전 - 이미 포화
```
세션표 16/16  ** 포화 - 새 세션은 조용히 버려진다 **
```
월드에 **한 번** 들어온 것만으로 16칸이 찼다. 그중 **아홉 칸**([7]~[15],
`…E0600`~`…E0C00` 등)은 조회 함수가 널만 돌려준 세션이었다 - 액터가 0 이라
이름표도 못 붙고 서버 여부도 못 가려 후보가 될 수 없는데 자리는 먹는다.
로그의 "세션 N" 줄은 이름표 붙은 일곱 개만 보였다. 그래서 아무도 표가 이미
꽉 찼다는 것을 못 봤다.

### 인플레이스 저장/로드 후 - 결정적
- **표의 주소 16개가 하나도 안 바뀌었다.** 로드가 만든 살아 있는 세션은
  자리가 없어 전부 버려졌다.
- 표의 모든 칸이 82초 넘게 안 불린 죽은 칸이 됐다.
- **게이트가 전부 닫혔다(열림 4 -> 0).**
- 그래서 세 경로가 갈렸다:

| 경로 | 선택 | 결과 |
| --- | --- | --- |
| 지급 패널(서버+게이트) | 없음 | 안전하게 막힘 = "세션 못 찾음" |
| 보관함(서버+호출최다) | `[0]` 죽은 세션 | 구동하면 0xC0000005 위험 |
| 동반자(서버+freshness+생존) | `[0]` 죽은 세션 | 구동하면 0xC0000005 위험 |

## 결론: 게이트가 유일하게 믿을 수 있는 생존 신호다

로드 직후 죽은 세션에 대해
- `session_looks_live`(`[세션+0x88]` -> `+1` 읽기)는 **"예" 를 줬다**. 그 자리가
  여전히 읽히기 때문이다.
- freshness 는 '가장 최근 것 대비' 로 재는데 표 전체가 똑같이 오래되면 기준이
  무너져 **통과시킨다**.
- `gate_object`(`[세션+0xA0]->[+0x68]->[+0x130]`)만은 **정확히 닫혔다**.

덧붙여, 세션 셋(`…E0200/E0300/E0400`)은 별개 접속이 아니라 **한 소유자의 인덱스
0/1/2** 다(`[+0xA0]` 이 같은 객체, `+0xA8` 이 번호). 게이트 객체는 셋이 공유하는
`CommonAdminActorComponent` 하나다.

설계에서 지킨 것 둘:

- 축출은 **마지막으로 액터를 낸 시각**이 가장 오래된 칸을 밀어낸다. 살아 있는
  세션은 게임이 쉬지 않고 부르므로 밀리지 않는다.
- 칸을 새로 잡을 때 **이름표를 먼저 지우고 주소를 맨 마지막에** 세운다. 순서가
  거꾸로면 읽는 쪽이 "새 주소 + 옛 이름표" 인 찰나를 보는데, 그것이 바로 새
  세션을 클라이언트로 오인해 후보에서 빼는 자리다.

F4 는 커밋 `eae3bf6` 이 고치려던 "그 세션에서 액터가 안 나왔습니다" 의 남은
절반이다 - 고급 목록에서 한 번 손으로 고르면 칸 번호에 못박혀, 로드로 표가
바뀌어도 "자동으로 다시 고르기" 를 누르기 전까지 풀리지 않았다.

## 다음 사람이 알아야 할 것

- 표는 이제 축출된다. `session_actor(i)`/`session_class(i)` 를 **인덱스로 들고
  다니면 안 된다** - 칸은 언제든 다른 세션 것이 될 수 있다. 세션은 주소로
  기억할 것(F4 가 그 예).
- 세션을 골라야 하면 `pick_drive_session(reader)` 를 쓴다. 새로 기준을 만들지
  말 것 - 그래서 세 번 깨졌다.
- 무언가 이상하면 먼저 `sessions` 를 찍어라. 추측보다 빠르다.
- 칸 수는 `kSeenCap`(grant.cpp) = 16, `session_capacity()` 로 밖에서 읽는다.
  월드 진입 한 번에 11칸을 쓰므로 여유는 크지 않다.
