# specguard div 자리는 한 가족이다 — 2944 재조사

**날짜:** 2026-09-20
**대상:** Crimson Desert Enhanced, exe **1.0.0.2944**
**앞 편:** `2026-09-18-game-update-2944.md` §4 (이 편이 그 절의 결론을 **보강**한다 —
"세 형태가 없다" 는 맞았고, 근거를 전량 검색으로 올리고 **새 자리 하나를 더했다**)

---

## 0. 무엇이 문제였나

2944 갱신 뒤 특수기능 아이템 크래시 가드가 **7곳 중 4곳만** 걸렸다.

```
WARN  특수아이템 가드: div 아님 @0x140EB26B4 (0x5BC348)
WARN  특수아이템 가드: div 아님 @0x140EA920F (0x4881C4)
WARN  특수아이템 가드: div 아님 @0x1421DB8D8 (0x0F8095)
WARN  특수아이템 가드: 4/7개만 설치 (base=0x140000000)
```

괄호 안은 그 자리의 첫 3바이트다 — `5B C3 48`(pop/ret) · `48 81 C4`(add rsp) ·
`0F 80 95`(jo). 셋 다 **남의 코드 한복판**이다.

앞 편은 네 갈래를 시도하고 *"정적으로는 못 찾는다, 남은 길은 크래시 로그 하나"*
로 닫았다.

---

## 1. 앞 조사의 빈틈 셋 (실측)

### 1.1 `div r/m64` 만 봤다

`0xC0000094` 는 **8/16/32/64 어느 크기에서도** 난다. `.code` 를 크기 무관으로
다시 훑었다(`.pdata` 함수 경계로 명령을 정확히 끊어서):

| 형태 | 개수 |
|---|---|
| `div reg` | 11,095 |
| **`div dword ptr [mem]`** | **5,841** |
| `idiv reg` | 649 |
| `idiv dword ptr [mem]` | 60 |
| `idiv qword ptr [mem]` | 19 |
| `div qword ptr [mem]` | **6** |

앞 조사가 본 것은 마지막 두 줄뿐이다. `div dword [rbp±X]` 553곳 · `[rsp+X]`
88곳은 시야 밖이었다.

### 1.2 `.pdata` 가 실행 섹션을 다 안 덮는다

| 섹션 | 크기 | `.pdata` 함수 | 덮은 본문 |
|---|---|---|---|
| `.code` | 81.9 MB | 218,224 | 65.8 MB = **80.3%** |
| `.didata` | 261.4 MB | 26,218 | 10.6 MB = **4.0%** |

`.pdata` 기반 "전수 조사" 는 `.code` 의 19.7%(16MB)를 못 본다. `.didata` 는
거의 전부 못 본다 — **알려진 자리 하나(`0xF83F65B`)가 거기 있다.**

### 1.3 `.pdata` 는 함수를 **조각낸다**

```
0x02409310..0x0240933E  (46 B)
0x0240933E..0x0240936C  (46 B)
0x0240936C..0x024093B2  (70 B)   <- 알려진 자리 0x240937D 가 여기
```

셋이 한 함수다. **연접 병합을 안 하면 알려진 자리를 놓친다**(실제로 놓쳤다).
병합하면 244,442 → 180,944.

> **규칙.** `.pdata` 로 함수를 돌 때는 **연접 항목을 병합**한다. 그리고
> "`.pdata` 전수" 는 전수가 아니다 — 덮는 비율을 먼저 재고 밝힌다.

## 2. 세 형태는 정말 없다 (전량 바이트 검색)

명령 경계 가정도 섹션 필터도 없이 **파일 397MB 전량**을 찾았다.

| 패턴 | 결과 |
|---|---|
| `48 F7 B5 F0 00 00 00` `div qword [rbp+0xF0]` | **0곳** |
| `48 F7 74 24 38` `div qword [rsp+0x38]` | **0곳** |
| `48 F7 75 C8` `div qword [rbp-0x38]` | **0곳** |
| *(대조)* `48 F7 77 08` `div qword [rdi+8]` | 1곳 |
| *(대조)* `49 F7 F6` `div r14` | 5곳 |
| *(대조)* `49 F7 F1` `div r9` | 36곳 |
| *(대조)* `49 F7 F0` `div r8` | 59곳 |

대조군이 전부 나오므로 방법이 성립한다. **세 형태는 2944 에 없다** — 추정이
아니라 전량 검색 결과다.

## 3. 일곱 자리는 한 가족이었다 (새 발견)

알려진 넷을 디스어셈블해 읽으니 흩어진 자리가 아니라 **하나의 관용구**였다.

```
mov  rax, gs:[0x58]                 ; TLS
mov  rbx, [rip + X]                 ; -> 전역 0x06D69458   (넷 다 같다)
mov  ecx, 0x1EC                     ; TLS 슬롯
cmp  byte [rcx + rdx], al
cmovne rbx, rax
call 0x01416C00                     ; 넷 다 같다
mov  r8, [rdi + 8]                  ; 구조체 +0x08 = 나누는 값
...
xor  edx, edx
div  r8
cmp  eax, [rdi + 4]                 ; 구조체 +0x04 = 상한
```

구조체는 `{+0x00 u32 first, +0x04 u32 상한, +0x08 u64 나누는값, +0x10 u64 limit}`
이고 곁들여 `call 0x38AB60` + `cmp byte [rax+0x2E0], 0` 이 자주 붙는다.

### 크래시가 나는 까닭은 둘이다

| 모양 | 예 |
|---|---|
| **(A)** 0 검사가 **아예 없다** | `0x240937D` `div [rdi+8]` |
| **(B)** 검사는 있는데 **0 갈래가 div 로 샌다** | `0xF83F65B` · `0x24095B4` |

(B) 의 실물:

```
0x0F83F629  mov  r8, [rdi + 8]
0x0F83F631  test r8, r8
0x0F83F634  jne  0xF83F63A      ; r8 != 0 이면 정상 갈래
0x0F83F636  mov  eax, [rdi]     ; r8 == 0 갈래인데
0x0F83F638  jmp  0xF83F659      ;   -> 그대로 div 로 간다
0x0F83F65B  div  r8             ; 0xC0000094
```

### 표식으로 전량을 훑었다

전역 `0x06D69458` + `xor edx,edx / div / cmp eax,상한` + 병합 함수로 397MB 를
훑으면 **딱 5곳**이 나온다.

| RVA | 형태 | 판정 |
|---|---|---|
| `0x0212CBC8` | `div r15` \| `cmp eax, r14d` | **새것 — 막혀 있다** (§5) |
| `0x0240919B` | `div r14` \| `cmp eax, edi` | 알려진 `kDivReg[1]` |
| `0x0240937D` | `div qword [rdi+8]` | 알려진 `kDivMem[3]` |
| `0x024095B4` | `div r9` \| `cmp eax, r8d` | 알려진 `kDivReg[2]` |
| `0x0F83F65B` | `div r8` \| `cmp eax,[rdi+4]` | 알려진 `kDivReg[0]` |

**알려진 넷이 전부 나온다(대조군 통과).**

0 검사 판정까지 돌리면 알려진 넷이 전부 (A) 또는 (B) 로 분류된다 — 역시 대조군
통과다. 가족 전체로는 **검사없음 31곳 · 0갈래가샌다 9곳 · 막힘 209곳**.

## 4. 건진 것 — `0xF83F6B4` (같은 함수 안의 쌍둥이)

**이미 가드를 거는 `kDivReg[0]`(`0xF83F65B`)과 같은 함수에, 89바이트 뒤,
똑같은 (B) 결함이 하나 더 있다.**

```
0x0F83F682  mov  r8, [rdi + 8]      ; 같은 구조체 칸
0x0F83F68A  test r8, r8
0x0F83F68D  jne  0xF83F693
0x0F83F68F  mov  eax, [rdi]         ; r8 == 0 갈래
0x0F83F691  jmp  0xF83F6B2          ;   -> 곧장 div 로
0x0F83F6B2  xor  edx, edx
0x0F83F6B4  div  r8                 ; 0xC0000094
```

### 지금 가드는 크래시를 89바이트 뒤로 옮길 뿐이다

```
0x0F83F65B  div r8            ; 우리 가드 -> eax=0, rdx=0
0x0F83F65E  cmp eax, [rdi+4]
0x0F83F661  jae 0xF83F719     ; 0 >= 상한 은 상한>0 인 한 **거짓** -> 안 뛴다
   ...                        ; 0xF83F682 에서 같은 0 을 다시 읽는다
0x0F83F6B4  div r8            ; 여기서 죽는다
```

즉 `kDivReg[0]` 만 거는 것은 **구조상 불완전**하다. 둘을 같이 걸어야 한다.

### 설치 안전 확인 (전부 실측)

| 항목 | 값 |
|---|---|
| 바이트 | `49 F7 F0 48 85 D2` = `div r8` + `test rdx,rdx` |
| `install_regdiv` opcode 검사 | `o[0]=0x49` · `o[1]=0xF7` · `o[2]=0xF0`(mod=11, /6) → 통과 |
| patch_len | 3 + 3 = **6** |
| 꼬리 위치 독립 | `48 85 D2` → REX 건너뛰고 `0x85`, modrm `0xD2`(mod≠0) → `specguard_tail_is_safe` 통과 |
| 창 안으로 뛰어드는 분기 | **0개** (함수 97명령 전수) |
| 기존 창과 겹침 | 없음 (0x59 떨어짐) |
| 0 갈래 의미 | `xor eax,eax; xor edx,edx` 뒤 꼬리 `test rdx,rdx` 재실행 → ZF=1 → 원래 `je 0xF83F719` 로 빠진다(게임이 의도한 조기 탈출과 같다) |

**대조군** — 같은 방법으로 `0xF83F65B` 의 patch_len 을 계산하니 **6**
(`div r8` 3 + `cmp eax,[rdi+4]` 3)이고 소스의 기존 값과 일치한다.

## 5. `kDivMem[0]` 의 후신으로 **보이는** 자리 (단정하지 않는다)

새로 나온 다섯째 `0x0212CBC8` 은 **게임이 스스로 막고 있다.**

```
0x0212CB86  mov [rbp+0xAC], r14d    ; 구조체 +0x04 상한
0x0212CB8D  mov [rbp+0xB0], r15     ; 구조체 +0x08 나누는 값   <- 스택에 인라인
0x0212CBB7  mov [rbp+0xB8], r8      ; 구조체 +0x10
0x0212CBBE  test r15, r15
0x0212CBC1  je   0x212CBEE          ; 0 이면 div 를 **건너뛴다**
0x0212CBC8  div  r15
```

명령 배열이 알려진 `0x2409130`(= `kDivReg[1]` 의 함수)과 **한 줄씩 같다.**
다른 점은 구조체가 인자 뒤가 아니라 **스택에 인라인**돼 있다는 것뿐이다 —
기준이 `rbp+0xA8` 이라 `+0x08` 은 `rbp+0xB0` 이다.

옛 `kDivMem[0]` 이 `div qword [rbp+0xF0]` 였으므로, 2850 에서 같은 구조체가
`rbp+0xE8` 에 있었다면 **정확히 같은 칸**이다.

> **단정하지 않는다.** 2850 exe 사본이 없어 대조가 불가능하고 스택 변위는
> 빌드마다 자유롭게 바뀐다. 말할 수 있는 선은 *"구조가 같고 2944 에서는
> 0 검사가 붙어 있다"* 까지다. 그래서 `kDivMem[0..2]` 는 **표에서 지우지 않고**
> 2850 값으로 남긴다 — opcode 검사가 거부하므로 안전하고, 남아 있어야
> `specguard_unsupported()` 가 참이 되어 지급 창이 경고한다.

## 6. 손대지 않은 후보 (기록만)

가족 안에서 (A)/(B) 로 분류됐지만 **특수기능 아이템 경로라는 근거가 없는**
자리들이다. 근거 없이 `.text` 를 더 고치지 않는다
(`TROUBLESHOOTING.md` §1.5 · §7.12).

```
0갈래가샌다 : 0x37662E · 0x3766C7 · 0x9D0E47 · 0x293199C · 0x2AC130F · 0x2B78709
검사없음(일부): 0x212AF60 · 0x212B010 · 0x212B1D5   (함수 0x212A870, 9434 B)
                0x2AC142A · 0x2AC144E · 0x2AC14AC   (함수 0x2AC11F0, 4900 B)
                0x28613A6 · 0x73DC3D · 0x73DC66
```

**다음에 크래시 로그가 나오면 이 목록에서 먼저 찾는다.**

  확인했다 — 항등식이 아니다.
