## 2. 재사용 가능한 핵심 인프라 (새 exe 기준)

- **지급 실행 지점**: 액터 조회 함수(RVA 0x2073710)가 게임 스레드에서
  depth==1·TLS 준비 상태로 도는 자리. request_give 가 요청을 걸면 그
  스레드가 집어 처리기를 SEH 가드로 부른다. **소켓 메시지 구동도 이
  인프라를 재사용**한다.
- **공유 작업 함수 0x26AFF70**(→jmp 0xFC5C6A0): 지급·소켓·소환이
  전부 `r9=0x11`, `rcx=[전역 0x6C29C50]`, `r8=&구조체` 로 이 함수를
  부른다. 아이템/엔티티 통합 라우터.
- **메시지 해석**: `resolve_cheat_message`(RTTI→vtable→서술자→처리기).
  소켓은 처리기가 인라인이라 `resolve_socket_deser`(vtable[2]=역직렬화)
  를 쓴다.
- **find_handler_call**(grant.cpp): `call` 뒤 성공저장(C7 즉시값 또는
  89 레지스터[앞서 xor 0])으로 처리기를 찾음. 스택인자(5+인자) 경로
  배제. 단위테스트 4개.

## 3. 어비스 소켓 구현 (Phase 2) — 다음 세션 최우선

### 3.1 완전히 해독된 와이어 형식

전문은 `specs/2026-09-04-socket-wire-format.md`. 요약:

소켓 = **뚫기(Add) → 장착(Push)** 두 메시지를 세션 서버 패킷으로
역직렬화(vtable[2]) 구동. 인벤토리 경로 메시지:
- 뚫기: `TrocTrAddSocketItemToInventoryReq` ID 2739, 역직렬화 0x293C560
- 장착: `TrocTrPushSocketItemToInventoryReq` ID 2354, 역직렬화 0x293B410
- (착용 장비: ...ToEquipSlotReq. 대상 형식 미확인 - 인벤부터.)

**헤더 5B**: `[ID u16 LE][00][본문길이 u8][00]` (본문길이=전체-5)

**대상 9B**: `[04][컨테이너핸들 u32][(슬롯<<16)|0x0002 u32]`
- 컨테이너핸들 = **세션마다 바뀌는 런타임 핸들**(0xB010 네임스페이스).
  실측 0xB0100116(세션A) → 0xB0100102(세션B). **동적으로 읽어야 함.**
- 슬롯 = 아이템의 인벤토리 위치(컨테이너 아이템 배열 인덱스로 추정).

**뚫기(Add) 데이터** — 모든 아이템 공통·고정(5슬롯 개방):
`02 00 05 00 00 00 01 00 00 02 00 00 03 00 00 04 00 00`

**장착(Push) 데이터** — `{소켓슬롯 u8, 보석슬롯 u16} × 5`:
예) `00 56 00 01 58 00 02 59 00 03 4A 00 04 49 00`
보석도 인벤토리에 있어야 하고 그 위치로 참조.

실측 캡처 원문(로그 `소켓 페이로드 [Add/인벤]`, `[Push/인벤]`):
```
세션A 혹한의절망: Add 04 16 01 10 B0 02 00 5A 00 + 뚫기고정
세션A          : Push 04 16 01 10 B0 02 00 5A 00 + 00 56 00 01 58 00 02 59 00 03 4A 00 04 49 00
세션B 에세리온  : Add 04 02 01 10 B0 02 00 56 00 + 뚫기고정
세션B          : Push 04 02 01 10 B0 02 00 56 00 + 00 60 00 01 5E 00 02 5D 00 03 5F 00 04 52 00
```

### 3.2 캡처 인프라 (이미 배포됨)

`socket_capture_install`(grant.cpp, camera 분석루프 init 에서 설치)이
6경로(Add/Push/Pop × 인벤/장비) 역직렬화를 후킹해 페이로드를 로그한다.
`dump_socket_payload` + 매크로 detour. **형식을 다 배웠으니 구현 시
이 진단 훅은 떼거나 남겨도 무방**(로그만 남김, 최대 40회).

### 3.3 구현 단계 (권장 순서)

1. **컨테이너 핸들 동적 확보** — 인벤토리 컨테이너 객체의 핸들 필드를
   찾는다. 메모리에 핸들 배열(`16 01 10 B0 72 03 10 B0 …`)이 있었고
   0xB010xxxx 네임스페이스. 모드가 찾는 인벤토리 컴포넌트/컨테이너에서
   이 핸들을 읽는 오프셋을 특정하는 것이 첫 정적 스텝.
   - 대안(빠른 v1): 캡처 훅이 세션당 1회 실제 소켓에서 핸들을 학습해
     재사용. 단 플레이어가 수동 소켓 1회 필요.
2. **아이템/보석 → 슬롯 매핑** — 모드 인벤 리더의 열거 인덱스가 슬롯일
   가능성이 크다(검증 필요). invlist 순서와 캡처 슬롯값 대조.
3. **와이어 조립** — 헤더+대상+데이터. 뚫기 데이터는 고정 재사용.
4. **전송** — 서버 세션 패킷을 만들어(지급의 packet 구성 참고,
   [+0x18]=payload ptr, [+0x10]=length, [+0x38] 플래그, payload[+3]=필드수)
   역직렬화 0x293C560/0x293B410 을 게임 스레드에서 SEH 가드로 구동.
   세션은 서버 세션(지급과 같은 best_server_session).
5. **흐름 배선** — 어비스기어 자동 지급 → 슬롯 찾기 → 뚫기 → 장착.
   UI: 로스터/지급 패널에 "소켓까지 지급" 버튼 또는 보관함 소켓 복원.

### 3.4 위험

**실제 게임플레이 거래라 틀리면 인벤토리 오염 가능**(옛 소켓-지급이
팅긴 것과 같은 성질). 버릴 세이브에서 단계별로 검증. SEH 필수.
슬롯/핸들이 틀리면 엉뚱한 아이템에 작용할 수 있으니 대상 확인을 엄격히.

## 4. 소환 (① 저수준 이관) — 리서치됨, 어려움

- 소환 치트 메시지의 처리기(find_handler_call 이 집은 0x2B6E530)는
  **아이템 라우터**(아이템 테이블 조회 + 0x3f5 태그 구조체 + 0x26AFF70
  r9=0x11). 캐릭터 스포너가 아니다. 캐릭터 키를 아이템으로 취급해
  **NPC 증발·무한로딩**을 냈다(버튼 제거로 방지 완료).
- 저수준 소환 = `SummonCharacterData`(52필드: _appearanceName,
  _summonSpawnType, _summonTagNameHash·_summoneeActionNameHash(해시),
  _position, _yaw, 도킹·소켓·캐치…). 옛 소환 크래시는 이 **이름 해시에
  널**을 넘긴 것. 로스터 내부 이름을 넣으면 넘을 가능성.
- 게임 자체 "탈것 부르기" `TrocTrCallSpecialVehicleByQuickSlotReq` 는
  **퀵슬롯 등록 탈것만** 부름(임의 탈것 키 불가).
- **판정**: 임의 스폰은 대공사·고위험·불확실(소환 실행 함수 특정 +
  최소 SummonCharacterData 조립 + 월드 문맥 + 버릴 세이브 테스트).
  소켓 구현 뒤 착수 권장. 전문 `specs/2026-09-04-game-update-break.md`.
