# 동반자 소환·획득 기능 구상 (2026-09-05)

포획 목록(`2026-09-05-catchable-companions.md`)의 야생 탈것·반려동물을
오버레이에서 **불러내고(소환) 내 것으로 만드는(획득)** 기능의 설계.
실측·정적 분석으로 확인한 사실 위에 세웠고, 아직 안 해 본 것은 그렇게
표시했다.

## 0. 한 줄 요약

- **획득은 메시지 하나로 좁혀졌다.** 길들이기 성공이 보내는
  `TrocTrHireMercenaryToTargetReq`(ID 2338, 본문 `u32 대상 액터 핸들 + u8`)
  를 역직렬화 구동하면, 월드에 있는 야생 개체를 로데오·친밀도 없이
  등록할 가능성이 있다. 소켓 Phase 2 와 같은 인프라다.
- **소환(없는 개체를 만들기)은 여전히 어렵다.** 대신 "이미 스폰된 야생
  개체를 찾아가기"는 지금 인프라로 되고 위험이 없다. 순서를
  **목록 → 찾아가기 → 획득** 으로 잡고, 진짜 소환은 마지막에 둔다.

## 1. 확인된 사실 (설계의 근거)

### 1.1 엔진 모델

- 탈것·마차·펫·가축·물고기는 전부 `MercenaryInfo` 타입(21종)의 하위이고,
  캐릭터 표의 `_mercenaryInfo`(+0xBE, 행 번호)로 타입이 정해진다. 야생
  개체는 내부 이름 `_Wild`, `_isHirable=1`.
- 소유 등록 = "고용". 정상 경로는 두 메시지뿐:
  - `TrocTrHireMercenaryFromInventoryReq` 2454 — 인벤 아이템(부적 6종만).
  - `TrocTrHireMercenaryToTargetReq` 2338 — **월드의 대상 액터**. 야생
    포획의 실제 등록 경로로 추정(길들이기 액션차트가 보낼 것).
- 치트 3종(`RequestHireMercenaryForCheatReq` 등)은 스텁.

### 1.2 HireMercenaryToTargetReq 역직렬화 (RVA 0x2960CA0, 정적)

```
헤더 5바이트 검사
읽기 4 -> 대상 핸들 u32      (rbp+0x7f)
읽기 1 -> 플래그 u8          (rbp-0x15)
[세션+0x96] != 0 게이트
0x2ADE280(세션, &결과, &핸들, 플래그)   ; 핸들 -> 액터 (전역 0x6C29C70+0x48 표)
   실패 -> 오류코드 [0x6BB7AE8] "대상 없음"
   액터+0x68 -> +0xB0 -> byte +0x3B0 을 읽어 분기   ; 대상 성질 플래그(미해독)
상태표 조회 0x1398000/0x1398540 ×2  ; FromInventory 와 같은 표. ==2 거부, ==1 필요
세션 vtable+0xE8 -> 컨텍스트
0x26AFF70(rcx=[0x6C29C50], r9=0x11, r8=&태그구조체)   ; 공용 라우터
```

본문 **5바이트**. 소켓·부적 구동과 같은 꼴이라 `resolve_socket_deser` +
게임 스레드 실행 지점 + SEH 가드로 그대로 태울 수 있다. **미확인**:
(a) 상태표의 키가 무엇인지(대상 캐릭터 키? 액터?), (b) `+0x3B0` 플래그가
"길들여짐" 상태인지 캐릭터 고유 성질인지. 둘 다 서버가 길들이기 없이
등록을 거부할 수 있는 지점이다. → §4 Phase 1 캡처로 푼다.

### 1.3 소환 쪽 후보와 판정

| 경로 | 실체 | 판정 |
|---|---|---|
| `SpawnCharacterCheatReq` | 처리기가 아이템 라우터. NPC 증발·무한로딩 냈음 | **금지** (기존) |
| 저수준 `SummonCharacterData` 조립(45필드, 이름 해시 등) | 소환 실행 함수 미특정 | 대공사·고위험 (기존) |
| `TrocTrCatchBySummonReq` 2386 (`u32 A, u32 B`) | 두 값 모두 0x29B3E10 로 **기존 액터 핸들 조회**(핸들 네임스페이스 0x2xxxxxxx 검사). 새 개체를 만들지 않는다 | 소환 아님. "붙잡기" 상태 제어에만 유용 |
| 아이템 사용 `ItemUseData_SummonCharacterWithCatch` (물고기 34종 방생) | 게임이 아이템 사용으로 캐릭터를 소환해 손에 쥐게 하는 **정상 경로**. 객체 0x40바이트에 캐릭터 키가 직접 없고, 소환 태그 해시(+0x30 = 0x5B86A7C3, 두 물고기 동일)로 `SummonItemData` 를 거치는 듯 | **유망하나 RE 필요**: 아이템→캐릭터 대응이 어디 있는지 |
| `SelectMercenarySpawnReq` 2894 (`u64 + float3`) | 이미 가진 동반자의 스폰 위치 선택 | 획득 뒤 "부르기"에 유용 |
| `Skill_CallVehicle/CallDragon` (수집 아이템 2종이 부여) | 가진 탈것 호출 | 획득 뒤 편의 |

### 1.4 액터 핸들을 얻는 방법 (지금 있는 인프라)

- grant.cpp 의 `det_entity_lookup`(엔티티 조회 훅)·`det_actor_getter` 가
  세션→액터를 잡고 있고, 핸들 조회 함수(0x29B3E10 계열)의 표는 전역
  `0x6C29C70+0x48`. 이 표를 걸으면 **월드의 살아 있는 액터 전부**와 그
  캐릭터 키를 얻는다(→ 캐릭터 표로 이름·용병 타입 해석).
- 카메라 초점 좌표·프리캠·`hold`(좌표 눌러쓰기) 인프라가 있어 "가장
  가까운 야생 개체" 계산과 이동이 된다.

## 2. 기능 구성 — "동반자" 패널

```
[동반자]  탭: 목록 | 근처 | 소유
────────────────────────────────────────────────
목록   타입▾ (말/특수/짐승/펫/가축/물고기)   종 검색 [    ]   ☑ 야생만
       키    내부 이름                 타입          [근처에서 찾기] [찾아가기]
       31378 Animal_Black_Horse_Wild   Vehicle_Horse  …
근처   월드 액터 중 동반자 타입인 것 (거리순)
       거리  이름                      상태         [획득] [붙잡기 해제]
소유   ClientMercenaryActorComponent 걷기 (D안)
       이름  타입  [부르기(SelectMercenarySpawn)] 
```

- **목록**: 캐릭터 표 × 용병 표 교차(이미 파이썬으로 한 것을 모드의
  roster 리더에 옮긴다). 한글 이름은 캐릭터 현지화 키 미해결이라 내부
  이름 우선, 도감 보고서 아이템 이름으로 보조.
- **근처**: 액터 표를 주기(1초)로 걸어 동반자 타입만 남기고 플레이어
  거리순 정렬. 여기서 **핸들**이 나온다 — 획득의 입력.
- **찾아가기**: 소환의 대체. 선택한 종의 살아 있는 개체가 근처에
  없으면 "이 종은 현재 로드된 지역에 없음"을 표시한다(스폰 지역 표는
  별도 조사).
- **획득**: 근처 표의 핸들로 2338 구동. 결과는 소유 탭 갱신으로 확인.
- **소환(진짜)**: 마지막 단계. §1.3 의 물고기 방생 경로를 리버스해
  "임의 캐릭터를 손에 쥔 채 소환"이 되면 붙인다.

## 3. 위험과 게이트

- **세이브 오염**: 획득은 실제 게임플레이 거래. 버릴 세이브 필수, SEH,
  1회 1건.
- **거부 경로는 안전**: 역직렬화가 자체 게이트(대상 없음·상태표)에서
  오류코드만 세우고 빠진다. 크래시보다 "아무 일 없음"이 기본 실패 모드다.
- **이중 등록**: 상태표 `==2` 거부가 게임 쪽에 있다.
- **소환 치트 재사용 금지**: 캐릭터 키를 아이템 라우터에 넣는 옛 경로는
  코드에서 제거된 상태를 유지한다.

## 4. 단계 계획 (각 단계에 실측 게이트)

**Phase 0 — 목록·소유 탭 (읽기 전용, 0 위험)**
roster 리더에 용병 타입 매핑(`_mercenaryInfo` 행 번호) 추가, 캐릭터 표에
`_isHirable`·`_Wild` 필터. 소유 탭은 `ClientMercenaryActorComponent`
레코드 구조 실측(probe 로 8개 인스턴스 덤프 → 캐릭터 키 자리 찾기).
게이트: 화면에 목록/소유가 맞게 나온다(스크린샷 대조).

**Phase 1 — 2338 캡처 (플레이 1회)**
`hook_one_socket("TrocTrHireMercenaryToTargetReq")` 를 학습원에 추가하고
야생마(또는 늑대) 길들이기를 **정상 플레이로 1회** 한다. 로그에 5바이트
본문·핸들이 찍히면 페이로드 확정. 같은 세션에서 대상 액터의
`+0x68→+0xB0→+0x3B0` 값을 길들이기 전/후로 읽어 게이트 의미를 푼다.
게이트: 핸들 형식·플래그 값·상태표 키가 문서화된다.

**Phase 2 — 근처 탭 + 획득 구동 (버릴 세이브)**
액터 표 걷기 → 근처 표. 길들이기 **안 한** 야생 개체 핸들로 2338 을
구동해 등록되는지 본다. 되면 로데오 생략 확정. 안 되면 오류코드로
어느 게이트인지 알 수 있다(대상 없음 0x6BB7AE8 / 상태표).
게이트: 소유 탭에 새 개체가 뜨고 게임이 정상.

**Phase 3 — 찾아가기**
근처에 없는 종은 스폰 지역이 필요하다. `SummonCharacterData_TerrainRegionAutoSpawn`
·`_terrainRegionSpawnPerCount`(CharacterInfo +0x2EC) 로 지역을 역추적할
수 있는지 조사. 단순 버전은 "현재 지역의 근처 표"만으로 시작.

**Phase 4 — 진짜 소환 (조사 후 결정)**
물고기 방생의 `SummonItemData`(13필드, `_summonTagNameHash` 등)에서
아이템→캐릭터 대응을 찾고, 임의 캐릭터로 바꿔 소환이 되는지 본다.
되면 "소환 → 근처 → 획득"이 한 흐름이 된다. 안 되면 Phase 3 으로 마감.

## 6. 하지 않기로 한 것

- 캐릭터 키만으로 "즉시 소유 추가"(월드 개체 없이). 메시지가 없다.
- 부적 스킬(`Active_Hire_*`)을 다른 캐릭터로 돌리기. 스킬 데이터가
  캐릭터를 고정하고, 스킬 표 조작은 상태표와 어긋날 위험이 크다.
- 드래곤·ATAG·배·마차: 야생 개체가 없어 이 기능의 범위 밖.


## 7. Phase 0 진행 (2026-09-05)

구현·빌드·297 테스트 통과. 배포는 게임 실행 중이라 거부됨 → 종료 후
`scripts/deploy.ps1`.

- `game/roster`: 캐릭터 표에서 `_mercenaryInfo`(+0xBE 행 번호)·
  `_isHirable`(+0x156)·`_isCatchable`(+0x148)·`_isUnique`(+0x14B) 를 읽는다.
  용병 표는 `+0x00` 이 포인터라 엄격 검증이 실패하던 버그를 느슨한
  판정(`looks_like_mercenary_manager`)으로 고쳤고, 행 번호를 키로 삼아
  21타입(`_mercenaryType` +0x20)을 읽는다. 이름 규칙 도우미
  `roster_is_wild`/`roster_species`. 단위테스트 `tests/roster_tests.cpp`.
- 패널 "탈것 · 용병 · 캐릭터"에 **동반자 탭** 추가: 타입 콤보(말·특수
  탑승물·탑승물·마차·반려동물·가축·물고기·곤충), "야생만"(기본 켬),
  "고용 가능만", 검색. 줄을 누르면 키가 클립보드로. 기존 "용병" 탭은
  "용병 타입"으로 바뀌어 21행을 보여준다.
- **소유 탭은 미구현.** `ClientMercenaryClanActorComponent`(1개)·
  `ClientMercenaryActorComponent`(10개)를 등록된 6종의 캐릭터 키로 걸어
  봤으나 소유 목록 배열을 특정하지 못했다(u16 키 스캔은 잡음이 많다).
  다음 수는 서버가 로드 시 보내는 `TrocTrMercenaryDataListAck` 역직렬화를
  캡처해 형식을 얻는 것 — 그런데 소켓 캡처 훅 인프라(`hook_one_socket`)가
  e2948b5 에서 제거돼 다시 들여와야 한다.

### 소켓의 "완전자동 불가" 결론이 여기에도 적용되는가

소켓이 막힌 이유는 **컨테이너 핸들(0xB010 네임스페이스)** 이 핸들 월드
객체에만 있고 모드가 읽는 서버 인벤토리와 링크가 없어서였다. 획득
메시지 2338 이 요구하는 것은 **액터 핸들(0x2xxxxxxx 네임스페이스,
0x29B3E10 이 전역 표 `0x6C29C70+0x48` 로 조회)** 이고, 이 핸들은 모드가
이미 잡고 있는 엔티티 조회 훅(`det_entity_lookup(mgr, out, id)`)의
`id` 로 지나간다. 즉 **핸들을 얻는 길이 소켓과 다르다** — 훅 로그로
"근처 액터 핸들 → 액터 → 캐릭터 키"를 세션 안에서 학습할 수 있다.
따라서 Phase 1(캡처)은 소켓 훅 복원 없이도 엔티티 조회 훅 확장으로
시작할 수 있다. 서버 게이트(+0x3B0 플래그·상태표)가 길들이기 상태를
요구하는지는 여전히 미확인이다.

### 게임 탭에 들어가면 소환은 따라온다 (확인)

부적으로 등록한 6종이 게임의 특수 탑승물/반려동물 탭에 나타났고, 그
탭의 부르기(`Skill_CallVehicle`/`ClientFrameEventCallMercenary`/
`TrocTrCallSpecialVehicleByQuickSlotReq`)는 **등록 목록**을 대상으로
한다. 획득이 같은 목록(서버 `MercenaryDataList`)에 들어가는 한, 소환은
게임 UI 가 해 준다. 그래서 이 기능은 "소환"을 직접 만들 필요가 없고
**획득만 성공시키면 된다** — Phase 4(진짜 소환)의 우선순위를 더 낮춘다.
