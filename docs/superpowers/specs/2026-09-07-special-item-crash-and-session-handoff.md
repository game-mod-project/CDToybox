## 특수기능 아이템 크래시 (해결됨)

### 정체
아이템 표(6,813개) 레코드 **+0x58 != 0** 인 32종 = 액티브/패시브 특수기능(스캔·
레이저·탐지·가젯 등) 탑재 장비. 목록: `docs/special-function-items.md`.
**키 크기와 무관**(차가운 어둠 판금 투구 key=1000380 저키인데 크래시, 어둠의
표식 391518536 고키인데 정상). 초기 "키 10M 가드" 가설은 반증되어 되돌림.

### 원인 = 정수 0으로 나누기 (0xC0000094)
치트 지급 아이템은 **특수기능 인스턴스 상태값이 0**. 게임이 렌더/착용/능력사용
경로에서 그 값으로 나눗셈 → div0 크래시. 저장/로드하면 게임이 값을 채워 정상.
크래시 덤프(`%LOCALAPPDATA%\Pearl Abyss\DumpCache\reports\*.dmp`, crashpad —
업로드되면 삭제됨) 파싱 + exe 디스어셈블로 지점 전부 특정.

덤프 파싱/디스어셈블 스크립트는 세션 스크래치패드에 있음(minidump 파서 +
capstone). 재현: `py -3` + capstone. items 덤프: `cdtb_probe items save <파일>`
(게임 실행 중, 오프라인 분석 가능. items_dump.bin = TEMP).

### specguard = 인라인 훅으로 각 div0 지점 가드 (src/game/specguard.{h,cpp})
"분모 0이면 나눗셈 건너뛰고 몫=0, 아니면 원래 div". 정상 아이템 무영향.
**rtti 비의존** — 모듈 베이스 + 확정 RVA + opcode 바이트 검증 후 패치. **overlay
on_frame(렌더 첫 프레임)에서 설치** (분석 루프의 늦은 지점이면 그 전에 지급/가방
열어 크래시남 - 실측). 7개 지점:
- 계열 A `div qword[mem]; lea ecx,[rax+1]` (가방 렌더): 0xEB1BF4, 0xEA874F, 0x21DA368
- `div qword[rdi+8]` (착용): 0x234EC7D
- 계열 B/reg `div r8;cmp eax,[rdi+4]`(가방 0xF064E5B), `div r14`(0x234EA9B),
  `div r9;`(특수능력 0x234EEB4)
디스크 전수 스캔으로 계열 A 3곳 확인, 착용/특수능력 함수영역(0x234E000~)
바이트 스캔으로 div 3개 확인. **새 빌드에선 RVA 재확인 필요**(바이트 불일치 시
자동 스킵).

**상태: 지급·가방 열기·착용·특수능력 사용 전부 크래시 없음(사용자 확인).**

## 표시 보정 healer (src/game/spec_heal.{h,cpp})

지급 직후 특수 상태값이 0이라 게이지·내구도 표시가 기본값. 저장/로드 없이
맞추려고, 32종의 {순번, 게이지최대(표+0x2C8), 최대내구도(표+0x400)} 테이블로
레코드 +0x2C=1, +0x30=게이지최대, +0x40=내구도 를 채움(분석 루프에서, +0x2C==0
인 것만). **한계: 게이지 현재치(+0x38)는 인스턴스별 계산값이라 재현 불가** →
게이지 충전(쿨타임) 로직은 안 돌고 0/max 로 보임. **저장/로드 1회면 게임이
런타임 상태를 세워 완전 정상**(특수능력 실제 작동 포함).

레코드 오프셋(저장본 vs 지급본 실측): +0x28=1, +0x2C=1, +0x30=게이지최대,
+0x38=계산값(예 81995/268462, 인스턴스마다 다름), +0x40=내구도(0xFFFF=없음),
+0x74=0x1000000.

## 미해결: 인플레이스 저장/로드 후 지급 세션을 못 찾음 ← 다음 세션 작업

### 증상
게임 재실행 직후엔 지급 정상. 그러나 **인플레이스 저장/로드 후** 지급 패널이
"플레이어 세션을 아직 못 찾았습니다"/"그 세션에서 액터가 안 나왔습니다"로 먹통.

### 지금까지 판명
- 지급은 세션을 게임 처리기에 넘겨 실행. 세션은 actor-getter 훅이 모은
  seen_sessions(16칸) 에서 고름. 처리기 게이트 = `[세션+0xA0]->[+0x68]->[+0x130]`
  (grant.cpp `gate_object`). 이게 풀려야 지급 성공.
- 신규 실행: 세션(예 …E0200, 서버 ServerInventoryActorComponent)의 게이트 정상 →
  지급됨(로그 "인벤토리 지급: 세션 0x…E0200 …" 확인).
- **인플레이스 저장/로드 후**: 표의 서버 세션(…E0300/E0400)들이 게이트가 끊겨
  ("사슬이 끊겼다") 지급 실패. 게이트 풀리는 세션이 표에 없음.
- 시도한 것: best_actor_index(호출1위)→stale 뽑음. best_live_session_index
  (last_seen)→작동 세션을 오래됐다고 제외. gate_object 검증→로드 후 통과하는
  세션이 아예 없어 "못 찾음". 세 방식 모두 로드 후엔 부족.
- 현재 코드: 지급 패널(grant_panel.cpp)·보관함은 각각 세션 선택. 지급 패널은
  gate_object 통과 서버 세션 중 호출최다(freshness 제거). 없으면 -1(막힘 표시,
  버튼 비활성 - stale 지급 안 함=안전). 보관함(stash_panel.cpp)은 원본
  best_actor_index(원복됨).
