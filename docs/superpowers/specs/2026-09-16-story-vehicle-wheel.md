## 1. 휠 클릭부터 스폰까지

실측으로 확정한 사슬(1.0.0.2850, ImageBase 0x140000000):

```
휠함수 0x29411E0
  └ 휠소환 0x2B78330
      └ 슬롯조회 0x2A22DE0        ← 오류 코드를 rdx 버퍼에 남긴다
          ├ 판정 0x20170E0        ← 거부 코드가 여기서 나온다
          └ 배달부 0x292B040      ← 실제 일. 인자 여섯
```

`0x2B78330` 은 `0x2A22DE0` 이 남긴 코드가 0 이 아닐 때만 알림(메시지 0x3F5,
본문 17바이트 중 +3 에 코드)을 띄운다. 코드가 0 이면 **조용히 반환**한다.

`0x2A22DE0` 의 꼬리는 **분기가 없다** — 판정을 통과하면 무조건 성공(0)을 쓰고
일은 전부 `0x292B040` 으로 넘긴다.

### 1-1. 훅을 걸 때 지킬 것

- 함수 시작은 **반드시** `tools/rtti/funcstart.py`(PE 예외 디렉터리 `.pdata`)로
  확정한다. "뒤로 훑어 `CC CC CC CC` 다음" 어림짐작은 셋 중 둘을 틀렸다.
- **호출 자리에서 인자 개수를 센다.** `0x292B040` 은 여섯인데 넷으로 걸어
  로드 중 게임을 팅기게 했다 — 원본이 `[rsp+0x20]`·`[rsp+0x28]` 에서 우리
  스택의 쓰레기를 읽는다.
- 알림 송신 `0x26B14E0` 은 `0xFB7F060` 으로 가는 **점프 썽크**다. 그 함수에
  건 훅이 게임을 팅기게 했다(`RIP 모듈+0x0FB7F0DE`). 걸지 않는다.

## 2. 관문들

### 2-1. 동반자 카테고리 — A.T.A.G. 를 막던 벽

`CharacterInfo._mercenaryInfo`(**+0xBE**, u16)가 동반자 카테고리다.

| 카테고리 | 뜻 | 예약 슬롯 |
|---|---|---|
| 1 | 말 | 메인 휠 1000006 |
| 2 | 드래곤 | 1000020 (7시) |
| 3 | A.T.A.G. | 1000019 (5시) |
| 5 | 특수 탑승물 | 메인 휠 1000006 |

메인 휠 칸(1000006)은 **1 과 5 만** 받는다. 그래서 카테고리 3 인 A.T.A.G. 는
메인 휠에서 거부됐다. 5 로 바꾸면 모든 판정이 특수 탑승물과 같아진다.

**`_vehicleInfo`(+0x6E)는 건드리면 안 된다.** 규칙이 아니라 *무엇이 나오는가*
를 정한다 — 말 값을 씌웠더니 드래곤 자리에서 말이 나왔다. "없음" 센티널은
0 이 아니라 **0xFFFF** 다.

월드에 나와 있는 동안은 **제 타입으로 되돌려야 한다.** 안 그러면 다른 계통이
그 종을 특수 탑승물로 보고 엉뚱한 화면을 연다(A.T.A.G. 개조 UI 자리에 말 UI).

### 2-2. 판정 `0x20170E0`

`.pdata` 로 잡으면 **0x20170E0 ~ 0x20175DC (1276바이트)**, 끝 32바이트는
코드가 아니라 **8칸 점프표**(0x20175BC)다.

```
r14 = [arg1+8] · rsi = arg2(오류버퍼) · ebx = arg3(슬롯색인) · rdi = arg4
0x201710D  0x200BDC0(arg4) 가 참이면 곧장 성공
0x2017116  rax = 0x382A30(&슬롯색인)     슬롯 정보 레코드
           [rax+0x80] != 0 → [rdi+0xEC] != 0xFFFF 만 보고 성공
           [rax+0x80] == 0 → [rax+0x41](0..7) 로 8갈래 분기
```

`rdi`(arg4)는 **배타적 합집합**이다 — 자기 갈래가 쓰는 칸만 채워져 있고
나머지는 비어(0xFFFF 또는 0) 있어야 한다.

| 갈래 | 진입 | 쓰는 칸 | 조회 대상 |
|---|---|---|---|
| 0 | 0x2017188 | +0xC8/+0xCA | 0x2074BA0 → 0x2079F00 |
| 1 | 0x2017256 | +0xDC | 관리자 `[0x6C2E330]` |
| 2 | 0x20172ED | +0xE0 | 관리자 `[0x6C2E328]` |
| 3 | 0x20173CE | +0xE8 | 0x382D80 |
| 4 | 0x2017448 | +0xCC | 0x384D50 |
| 5 | 0x201746D | +0xEA | 0x3830B0 → 0x17B1850 |
| 6 | 0x2017436 | +0x100 | 0 이 아니기만 하면 된다 |
| **7** | 0x201749D | **+0xD8** | 슬롯의 `+0x58` 목록(개수 `+0x60`) |

**갈래 7 이 동반자 갈래다.** `[rdi+0xD8]`(카테고리)가 슬롯의 허용 목록에
있어야 하고(§2-1 의 "1·5 만" 이 이 목록이다), 그 뒤 `[r14+0xA0]`·`[…+0xD0]` 가
살아 있어야 하며, 마지막으로 `0x2096C30` 조회가 무언가를 찾아야 한다.

### 2-3. 거부 코드 여덟 개

전역들은 `.bss` 라 파일에서는 못 읽는다. 실행 중 게임에서 읽었다:

| 기록 자리 | 전역 | 코드 | 조건 |
|---|---|---|---|
| 0x201713E | — | **0** | 성공 |
| 0x20171B0 | 0x6BBBC08 | 4257992575 | 갈래0: 0x2074BA0 이 널 |
| 0x2017235 · 0x20172E6 · 0x20173AE | 0x6BBCA10 | 3825518385 | **범용 거부** |
| 0x2017242 | 0x6BBCDE4 | 103837360 | 갈래0: 조회 결과가 비었다 |
| 0x20174DA | 0x6BBC014 | 1172209432 | 갈래7: `+0xD8` 이 0xFFFF |
| 0x2017516 | 0x6BBC0C0 | 300143221 | 갈래7: 카테고리가 슬롯 목록 밖 |
| 0x201752F | 0x6BBC24C | 2542652655 | 갈래7: `[r14+0xA0]` 널 |
| 0x2017548 | 0x6BAA568 | 1773986448 | 갈래7: `[…+0xD0]` 널 |
| **0x20175A7** | 0x6BBC008 | **4205559856** | 갈래7: **등록 조회가 빈손** |

**드래곤이 받던 것이 4205559856** 이다. 그 앞의 카테고리 관문은 통과한다 —
막혔다면 300143221 이 나온다.

### 2-4. 등록 — "호출할 수 없는 위치" 의 진짜 정체

`0x2096C30(주인, 카테고리, 슬롯색인)` 이 **카테고리별 동반자 목록**에서
항목을 찾는다. 표 배치는 `ReserveSlotInfoManager` 와 같다:

```
map = 주인 + 0x18
  +0x30 버킷 수 · +0x34 0이면 없음 · +0x40 버킷표(0x100 간격) · +0x48 레코드
  버킷: [0] 항목 수 · +8 부터 {u32 키, u32 색인}
  레코드: +0x04 u16 키(카테고리) · +0x08 항목배열 · +0x10 개수
```

못 찾으면 **전역 0x6BB80C0**(`+0x20 = 0xFFFF`, `+0x28 = -1`)을 돌려주고,
갈래 7 이 그 두 값을 보고 거부한다.

항목 하나가 **동반자 하나**다:

| 칸 | 뜻 |
|---|---|
| +0x20 | u16 **종행** |
| +0x28 | i64 **동반자 번호** |
| +0x148 | u16 **올려 둔 휠 칸** (0xFFFF = 안 올려놨음) |

실측(2026-09-16):

```
카테고리=1 -> 찾음 (종행 4100  번호 1000109)   말
카테고리=3 -> 찾음 (종행 6818  번호 1000602)   A.T.A.G.
카테고리=2 -> 빈손                              드래곤
  카테고리 2 레코드 - 항목 2개 · 둘 다 칸=0xFFFF
```

**드래곤 항목은 비어 있지 않았다** — 종행 7008 · 번호 1000483 / 1000724 로
멀쩡히 있었고 `+0x148` 만 0xFFFF 였다. 즉 **잠긴 게 아니라 휠 칸에 안 올라가
있었다.** 그 두 바이트를 채우자 거부가 사라졌고, **쓰기는 세이브에 남아**
재시작 세 번을 넘겼다.

**빈 칸을 다 채우면 안 된다.** 말 카테고리에도 `+0x148 = 0xFFFF` 인 항목이
다섯이고 전부 진짜 동반자다(종행 4073·4075·3643·3753·**6679 프라이든**) —
가진 것을 다 휠에 올려놓지는 않기 때문이다. 채울 때는 종행을 못 박는다.

## 3. 기능

플레이어 치트 > **탈것 휠**.

| 설정 | ini | 기본 | 하는 일 |
|---|---|---|---|
| 드래곤·ATAG 를 특수 탑승물 칸으로 옮기기 | — (런타임) | 끔 | 지형 제한 완화 + (아래가 켜져 있으면) 카테고리 교체 |
| 동반자 칸까지 옮기기 | `wheel_swap_slot` | **1** | 끄면 **지형 제한만** 풀고 칸은 제자리 |
| 휠 칸에 등록까지 채우기 | `wheel_fill` | 0 | 위에서 고른 종의 `+0x148` 을 채운다 |
| 소환 진단 훅 | `summon_diag` | 0 | 조사용. 일상 플레이에서는 끈다 |

얹기가 **두 가지를 같이** 하고 있던 것이 하루치 혼선의 원인이었다 — 칸을
옮기면 카테고리가 5 로 가서 카테고리 2 에 채운 등록이 안 닿고, 끄면 등록은
닿지만 지형이 조여진다. 그래서 `wheel_swap_slot` 으로 갈랐다.

등록은 세이브에 남으므로 한 번 채운 뒤에는 `wheel_fill` 을 꺼도 유지된다.

## 4. 마지막 한 겹 — 클라이언트 밖이다

거부가 사라진 뒤에도 드래곤은 월드에 안 나온다. A.T.A.G.(나온다)와 같은 자로
`0x292B040` 의 인자 여섯·반환·**출력 버퍼 둘**까지 쟀다:

| | 반환 | `[a5]` | `[a6]` |
|---|---|---|---|
| A.T.A.G. (슬롯키 1000019) | `0xF4240` | …`19` | **0** |
| 드래곤 (슬롯키 1000020) | `0xF4240` | …`1A` | **0** |

`[a5]` 의 `0x19`/`0x1A` 는 슬롯 번호(25·26) 그 자체다. **다른 것이 없다.**

통과한 관문 전부: 카테고리 · 예약 슬롯 조회 · 거부 코드 판정(갈래 7 전 단계) ·
등록 목록 · 호출 지형 요구 · 지면 거리 · 탈출로 그룹 · 최대 고도 · 복셀 타입 ·
소환 배달부와 그 출력 버퍼 둘.

**드래곤은 이 모두를 A.T.A.G. 와 똑같이 통과한다.** 그런데 A.T.A.G. 만 나온다.
실제 스폰은 클라이언트가 결정하지 않는다.

### 4-1. 다시 판다면

클라 안이 아니라 **주고받는 메시지**다. 지금까지의 훅은 전부 소환 요청
*조립* 단계이고 응답 처리는 한 번도 안 봤다. `동반자 캡처` 의 11경로는 휠
소환을 안 덮는다 — **말이 나올 때도 안 찍힌다**(대조군으로 확인).
