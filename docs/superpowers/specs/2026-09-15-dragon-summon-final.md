# 스토리 탈것(블랙스타 드래곤) 소환·탑승 — 최종 조사 (2026-09-15)

원본 스토리 탈것(블랙스타 드래곤 `Riding_Dragon_1`)을 스토리 없이 소환·탑승
가능하게 만드는 작업의 **최종 결론**. 앞선 핸드오프
`2026-09-14-dragon-wheel-handoff.md` 를 **정정·초월**한다(그 문서의 전제였던
"게이트 0x2ACA250 = 소환 관문" 은 라이브로 반증됐다).

## 0. 결론 먼저

- **현지화(이름 표시) 버그는 고쳤다** — 확실한 결과물. [§5]
- **드래곤을 휠로 네이티브 소환·탑승 가능하게는 못 만들었다.** 스토리 탈것이
  게임의 서버 주도 흐름에 여러 겹으로 얽혀 있어, 런타임 메모리·데이터 플래그
  어느 레버로도 `0x2A22DE0(1000020)` 실패를 못 풀었다. [§1~§4]
- **스폰(겉모습)까지는 된다** — 거리검사 우회 + 2894 로 드래곤이 월드에
  나타난다. 그러나 그 액터는 탈것/조종 컴포넌트가 없는 "껍데기"라 탑승 불가.

## 1. 실제 소환 경로 (핸드오프 정정)

**휠 클릭의 실제 경로는 게이트 `0x2ACA250` 이 아니다**(라이브 반증: 사자가
휠로 소환됐는데 게이트 훅 0회). 두 경로가 있다:

| 경로 | 사슬 | 비고 |
|---|---|---|
| **A. 위치선택 2894** | `2894 → 0x2AD1640(소환작업) → 거리검사 0x2AD1C9E → 게이트 0x2ACA250 → 0x2ACA441 → 스폰` | 드래곤을 **명부번호(1000483)** 로 스폰. 거리검사가 벽. |
| **B. 휠 클릭(클라 로컬)** | `0x2941350 → 0x2B78330 → 0x2A22DE0(번호해시 1000020)` | 드래곤을 **휠 해시번호(1000020)** 로 소환. 결과 0(실패). |

**두 번호 체계가 분리**돼 있다: 휠은 번호 해시 `0x6C2E300`(~28개)의 번호를
쓴다 — 사자 슬롯=1000006, 드래곤 슬롯=1000020 — 이건 명부(clan) 번호(사자
1000414, 드래곤 1000483)와 **다르다**. 종 교체는 명부 1000483 을 바꾸지만
휠은 1000020 을 참조하므로 **서로 안 닿는다**.

## 2. 경로 A — 거리검사 우회로 스폰까지 성공, 탑승 실패

- 2894(SelectMercenarySpawn) 는 `0x2AD1640` 안 **거리검사**(`0x2AD1C9E`:
  `(탈것위치-목표)² ≤ 256` = 반경 16)에서 드래곤을 거부(`0x7C181D9E`,
  전역 `[0x6BBC034]`). 사자는 이미 월드(근처)라 통과, 드래곤은 멀어 거부.
- **`0x2AD1C9E` 의 `jbe`(6바이트 `0F 86 8F 00 00 00`)를 `jmp`(`E9 90 00 00 00 90`)
  로 패치**하면 거리검사가 항상 통과 → 2894 로 드래곤 스폰 성공(게이트 키=0x2,
  소환작업 코드 0x0, 명부 스폰핸들 B010000x 붙음). **드래곤이 하늘에 뜬다.**
- 그러나 탑승 불가: 라이브로 **드래곤 액터 `[+0x68]` 컨트롤 컴포넌트 = null**
  (플레이어는 있음). 강제 스폰은 겉모습만 만들고 탈것/조종 알맹이가 없다.
- 탑승 메시지도 전부 무효:
  - `TrocTrRideOnVehicleReq`(2106, 본문 `[u32 핸들A][u32 핸들B][u8 좌석]`):
    양쪽 순서 다 결과 0인데 실제 탑승 안 됨. 핸들러 `0x2B7CB50` 이 탈것을
    "탈 수 있는 상태"로 인정 못 함.
  - `TrocTrReserveSummonAndRideAck`(2503): **Ack(서버→클라)** 라 모드의
    구동(클라→서버 요청 경로)으로는 클라 수신 핸들러가 안 돌아 무반응.
  - `TrocTrChangePlayerbleCharacterReq`(2494): 인간 리드 전환용, 탈것 무효.

## 3. 경로 B — 휠 클릭의 벽 (못 뚫음)

- 휠 클릭 → `0x2A22DE0(r8=1000020)` → **결과 0**. 사자(1000006)도 결과 0인데
  사자는 이미 월드라 전환됨. 즉 `0x2A22DE0→0` 자체는 판별점이 아니고, 실제
  전환/스폰은 그 뒤 로직에서 갈리는데 드래곤은 **월드에 없어서** 막힌다.
- `0x2A22DE0` 은 진입에서 번호해시 `0x6C2E300` 조회(1000020 **찾음**) 후
  스폰 구성부로 가지만, 드래곤에 대해 0(핸들 없음)을 낸다. 구성부가 크고
  복잡해(0x580 스택) 단일 실패 분기를 정적으로 특정 못 함.
- **1000020 은 실데이터를 참조**한다(인덱스 26 → 그룹 26 → 타입행 2 = 드래곤).
  placeholder 가 아님. 그런데도 스폰이 0.

## 4. 안 통한 레버 (닫힌 길)

- **런타임 characterinfo 플래그 편집**: 드래곤 템플릿(행 7008) vs 와이번(6804)
  diff 로 `_isUnique`(+0x14B: 1 vs 0)·countable(+0x16E/16F) 차이를 찾아
  드래곤을 와이번처럼 바꿔도 휠 클릭은 여전히 `0x2A22DE0→0`. **소환 벽은
  characterinfo 플래그가 아니다.** (로드 후 런타임 편집이라 소환 표가 재구축
  안 돼서일 수도 있음 — 데이터파일(DMM) 편집이면 다를 여지는 남음.)
- **강제 스폰 재활용**: 경로 A 로 스폰한 드래곤(1000483)을 휠이 못 찾음
  (휠은 1000020 참조). 두 번호 공간이 분리돼 링크가 안 됨.

## 5. 현지화(이름 표시) 버그 — 고침 ✓

- **증상**: 로스터 패널(내 동반자·근처·탈것·캐릭터)의 "이름" 열이 전부 "-".
  아이템 이름도 0개. 로그 "표시명 0개".
- **원인**: `discover_roster`(roster.cpp)는 `g_ready` 면 즉시 반환 — **한 번
  빌드하면 재라벨 안 함**. 현지화가 카탈로그보다 **늦게 로드**되면 첫 빌드가
  표시명 0개로 영구 고정. 아이템 표엔 있던 "현지화 올라오면 재빌드" 재시도가
  로스터엔 없었다. (현지화 시스템·오프셋은 정상 — 패턴 1회 매칭, 전역 사슬
  라이브 유효.)
- **수정**: `g_have_labels` 원자 플래그 추가. 표시명이 붙을 때까지(현지화
  준비될 때까지) 다음 틱에 재빌드(아이템 표와 동일한 재시도). 목록은 `g_ready`
  로 계속 보임.
- **검증**: 로드 직후 표시명 0개 → ~7초 뒤 **표시명 7250개**, 아이템 6741개.

## 6. 참고 모드 (Nexus 2745, DMM)

"GoldenStar 2x Swap BlackStar Dragon" 은 **런타임 해킹이 아니라 DMM 데이터
모드**다: `characterinfo.pabgb` 의 `Riding_Dragon_1` 항목 `lookup_22`(메시)를
GolemDragon 외형으로 스왑 + 큰 모델 파일 교체. 즉 **이미 가진/소환되는 대상을
"리스킨"** 하는 것이지, 미획득 스토리 개체를 소환되게 만드는 게 아니다.
커뮤니티도 이 방식(리스킨)으로 우회하는 것으로 보인다. DMM·pabgb 는 게임
PAK 안에 묶여 있고 현재 게임엔 DMM 미설치.
