# 어비스 소켓 와이어 형식 (2026-09-04, 실측 캡처로 완전 해독)

업데이트로 소켓이 아이템 생성 치트에서 빠지고 전용 게임플레이 메시지로
옮겨졌다. 소켓은 막힘/뚫림 상태가 있고(`SocketInfo._isBlocked`),
**막힌 소켓 → 뚫기 → 보석 장착** 흐름이다. 옛 방식(생성 치트에 소켓
바이트를 미리 채움)은 뚫기를 건너뛰어 새 게임이 거부했다.

## 캡처 방법

`socket_capture_install`(grant.cpp)이 소켓 메시지 6개(Add/Push/Pop ×
인벤/장비)의 역직렬화(vtable[2])를 후킹해, 게임이 실제로 소켓을 뚫고
장착할 때 들어오는 와이어 페이로드(패킷 +0x18 포인터, +0x10 u16 길이)를
로그한다. 사용자가 인벤토리 아이템 3개에 5슬롯 뚫기+5기어 장착을
실제로 해서 다음을 얻었다.

## 메시지·헤더

| 조작 | 메시지 | ID |
|---|---|---|
| 뚫기 | TrocTrAddSocketItemToInventoryReq | 2739 (0x0AB3) |
| 장착 | TrocTrPushSocketItemToInventoryReq | 2354 (0x0932) |
| (장비 경로) | ...ToEquipSlotReq | Add 2979 / Push 등 |

헤더 5바이트: `[메시지ID u16 LE][00][본문길이 u8][00]`. 본문길이 =
전체길이 - 5. 역직렬화가 `[패킷+0x10] - 5 == [payload+3](필드수)` 로
검사한다.

## 대상 아이템 참조 (본문 앞 9바이트) — 핵심

세 아이템의 [Add] 대상을 나란히 비교(딱 한 바이트만 다름):

```
혹한의 절망(키15901):   04 16 01 10 B0 02 00 5A 00
데메니스 전기톱:        04 16 01 10 B0 02 00 39 00
채석 손 드릴:           04 16 01 10 B0 02 00 05 00
```

구조: `[04 u8][컨테이너핸들 u32][(슬롯<<16)|0x0002 u32]`
- `04` : 참조 종류
- `0xB0100116` : **인벤토리 컨테이너 핸들, 세션 고정.** 메모리에서
  `16 01 10 B0 72 03 10 B0 84 03 10 B0 …` 핸들 배열의 첫 항목이다
  (0xB010 = 핸들 네임스페이스). 세션마다 바뀔 수 있어 동적으로
  읽어야 한다.
- 슬롯 = 아이템의 인벤토리 위치(90·57·5). `(슬롯<<16)|2` 로 인코딩.

## 조작 데이터 (대상 뒤)

**뚫기(Add) — 모든 아이템 공통·고정** (5슬롯 전부 개방):
```
02 00 05 00 00 00 01 00 00 02 00 00 03 00 00 04 00 00
```
(`05 00 00 00` = 슬롯 5개. 그대로 재사용 가능.)

**장착(Push) — {소켓슬롯 u8, 보석슬롯 u16} × 5**:
```
00 56 00  01 58 00  02 59 00  03 4A 00  04 49 00
```
소켓슬롯 0..4 에 보석슬롯 0x56·0x58·0x59·0x4A·0x49(인벤토리 위치).
즉 보석도 인벤토리에 있어야 하고 그 위치로 참조한다.

## 처리 방식 (역직렬화 인라인)

소켓 메시지는 처리기가 역직렬화 안에 인라인이다. 파싱 후
`call [rax+0xe8]`(세션에서 액터), `mov r9d,0x11`, `lea r8,[구조체]`,
`mov rcx,[전역 0x6C29C50]`, `call 0x26AFF70`(지급·소켓 공유 작업함수)로
라우팅한다. 즉 치트처럼 별도 처리기를 못 부르고, **와이어 페이로드를
만들어 역직렬화(vtable[2])를 서버 세션 패킷으로 구동**해야 한다.

## 구현 계획 (Phase 2)

1. **컨테이너 핸들 확보** — 0xB0100116(세션 고정)을 인벤토리 시스템에서
   읽는다. 핸들 배열의 첫 항목. (또는 캡처 훅으로 세션당 1회 학습.)
2. **아이템·보석 슬롯** — 모드의 인벤토리 리더가 위치를 안다.
3. **메시지 조립** — 헤더+대상+데이터로 Add(뚫기)·Push(장착) 와이어를
   만든다.
4. **전송** — 서버 세션 패킷을 만들어 역직렬화를 게임 스레드에서 구동
   (SEH 가드). 지급 치트의 실행 지점 인프라 재사용.
5. **흐름 배선** — 어비스기어 자동 지급 → 슬롯 찾기 → 뚫기 → 장착.
   이걸로 옛 "소켓 미리 채워 지급"을 결과적으로 대체한다.

## 미확정 (구현 전 확인)

- 컨테이너 핸들 0xB0100116 이 세션 재시작마다 바뀌는지(→ 동적 읽기
  필수인지). 재시작 후 1회 캡처로 확정.
- 장비 경로(EquipSlot)의 대상 형식(슬롯 번호 기반일 가능성).
- Push 의 보석슬롯이 아이템과 같은 컨테이너 기준인지.
