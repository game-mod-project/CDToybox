# 게임 갱신 뒤 재확인 절차

**날짜:** 2026-09-01
**계기:** Steam 패치 (컷신 립싱크·카린 채석장 기중기·떠돌이 상인 충돌 수정)
**결론:** 우리 쪽 가정은 전부 그대로다. 고칠 것이 없다.

## 무엇이 바뀌었나

| | 이전 | 이후 |
|---|---|---|
| EXE 크기 | 363,522,456 | **361,256,856** (-2.2MB) |
| SizeOfImage | 0x15F95000 | 0x15D6C000 |
| 섹션 이름 | `.rdata` `.text1` `.00cfg` … `.sbss` | **`.debug` `.sbss` `.xpdata` … `.shared`** |

**섹션 이름이 통째로 바뀌었다.** Denuvo 가 빌드마다 무작위화한다. 그런데
RVA 와 크기는 그대로다 - 실행 섹션은 여전히 RVA 0x1000(77MB)과
0x6B32000(239MB)이고, 이름만 `.rdata`→`.debug`, `.sbss`→`.shared` 로
바뀌었다.

`.shared`(구 `.sbss`)의 VirtSize 만 0xEFEE910 → 0xEDC565C 로 줄었다.
2.2MB 감소는 여기서 온다.

**문서에 적어 둔 규칙이 이걸 막았다** — "섹션 이름으로 코드 영역을
고르면 안 되고 `IMAGE_SCN_MEM_EXECUTE` 를 봐야 한다". 이름으로 골랐다면
이번 패치에 전부 깨졌다.

## 무엇이 그대로인가

전부 실측으로 확인했다.

| 대상 | 결과 |
|---|---|
| `LocalizationStringBase::str()` 패턴 | 이미지 전체에서 **여전히 1곳**, 주소도 `0x1410d6080` 그대로 |
| 현지화 시스템 전역 | `0x146259478` 그대로 |
| `ItemInfoManager` RTTI 탐색 | 정상 |
| 아이템 개수 | **6,810개** 그대로 |
| 이름이 풀리는 개수 | **6,738개** 그대로 |
| 편전(2200) 이름 키 | `9448928051312` 그대로 |
| 레코드 `+0x18` 최대 스택 | 100 그대로 |
| 레코드 `+0xA8` 분류 | 20 그대로 |
| 레코드 `+0x210` 등급 | 그대로 |

아이콘 아틀라스가 쓰는 `itemtable.bin` 은 패치 전에 뜬 것이지만, 키·
이름·개수가 모두 같으므로 그대로 유효하다.

## 갱신 때마다 할 것

### 0. 먼저 이것부터 (2026-09-18 추가)

```powershell
py -3.14 tools/rtti/recheck.py "E:\SteamLibrary\steamapps\common\Crimson Desert\bin64\CrimsonDesert.exe"
```

아래 1~3번과 **메시지 ID 대조**를 한 번에 한다. 손으로 적은 목록이 아니라
**소스를 읽어** 대조표를 만들므로 상수를 더해도 도구를 안 고쳐도 된다 —
갱신 때마다 목록이 낡아 빠뜨리던 것을 막으려고 그렇게 지었다.

읽는 법:

- **3번(메시지 ID)에 `**` 가 있으면 그것부터 고친다.** RVA 는 틀리면
  프롤로그·opcode·창 8바이트 검사가 걸러 주지만 **메시지 ID 에는 그 그물이
  없다** — 옛 번호가 다른 메시지에 재사용되면 조용히 다른 처리기가 돈다
  (1.0.0.2944 에서 실제로 그럴 뻔했다).
- 2번(AOB)에서 `**` 는 진짜 회귀다. 유일하지 않은 것이 정상인 패턴에는
  소스에 `// @aob <n|any> - 이유` 가 달려 있고 도구가 그것과 견준다.
- 4번(고정 RVA)은 **판정을 사람이 한다.** 자동 판정은 거짓 안심을 만든다.
  "데이터" 로 표시된 것은 정적으로 안 갈린다 — 게임을 켜고 프로브로 본다.

소스 쪽 약속 둘. 상수를 더할 때 같이 지킨다:

- 메시지 ID 상수 위에 `// @class <RTTI 이름>` 한 줄. 이름은 갱신을 안 타므로
  그 한 줄이 재도출의 전부가 된다.
- 유일하지 않아도 되는 AOB 위에 `// @aob <n|any> - 이유`.

### 0.5 로그를 읽을 때는 `.prev` 를 기준선으로 쓴다 (2026-09-18 추가)

갱신 뒤 로그에 warn 이 보이면 **그것이 새 것인지부터 본다.** `.prev` 는 갱신
**전** 실행이라 그대로 기준선이다. 기준선 없이 읽으면 오래된 warn 을 이번
갱신의 회귀로 오판한다 — 2944 에서 실제로 그럴 뻔한 것이 둘 있었다
(`엔티티 조회 함수를 못 찾았다` 는 2760 부터 있던 것, `문: 사슬이 끊겼다` 는
갱신 전 137건 → 지금 16건으로 **줄었다**).

```bash
for f in CDToybox.log CDToybox.log.prev CDToybox.log.prev2; do
  echo "$f"; grep -oE 'WARN  [^0-9]{6,40}' "$f" | sort | uniq -c | sort -rn | head
done
```

### 그다음 (도구가 못 하는 것)

순서가 곧 절차다. 앞의 것이 깨지면 뒤는 볼 것도 없다.

1. **EXE 크기·수정 시각·해시**를 비교해 실제로 바뀌었는지 본다.
2. **섹션 표**를 뜬다. 이름은 무시하고 `IMAGE_SCN_MEM_EXECUTE` 인
   섹션의 RVA·크기를 본다.
3. **`str()` 패턴이 이미지 전체에서 1곳만 일치**하는지 본다. 두 곳
   이상이거나 0곳이면 현지화 경로가 깨진 것이다.
4. 게임을 켜고 `cdtb_probe items 3` 으로 **개수와 첫 항목**을 본다.
   6,810 / 6,738 / 편전이 나오면 표는 그대로다.
5. `cdtb_probe items rec 2200` 으로 **레코드 오프셋**을 대조한다
   (+0x18=100, +0xA8=20, +0x210).
6. **지급을 한 번 눌러** 로그를 본다. `구동 건너뜀: 확인되지 않은 자리 +<RVA>`
   가 찍히면 그 RVA 를 `bin64/CDToybox.ini` 의 `drive_sites` 에 적는다 —
   **다시 빌드할 필요 없다**(2026-09-18 추가). 이 상수는 2850·2944 두 번 연속
   갱신에 죽었고 두 번 다 증상이 "지급·획득이 조용히 안 된다" 였다.
7. **매니저 전역**(지식·예약슬롯·조건·GPV·구역)이 "표를 아직 못 잡았습니다"
   로 나오면 `cdtb_probe` 로 인스턴스를 잡아 그 주소를 담은 전역을 찾는다.
   포인터 은행 안이라 정적으로는 안 갈린다 — 2850·2944 두 번 다 그랬다.

## 곁다리로 확인한 것 (가설 기각)

분류 번호(`+0xA8`)가 현지화 카테고리 8 / 필드 0x80(분류명 표)의
엔티티 번호일 것이라 보고 20·73·83·45 를 조회했으나 **전부 0건**이다.
엔티티 3 이 '화폐' 로 나왔던 것은 번호 체계가 겹친 우연이었다.

아이템에서 분류명으로 가는 표는 여전히 못 찾았다. 분류 74종 중 44종은
crimsondb.gg 유형과의 대조로 이름을 붙였고 나머지는 번호로 둔다.
