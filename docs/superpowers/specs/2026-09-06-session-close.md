# 세션 정리 — 동반자 추가 기능 (2026-09-06)

주제: **오버레이에서 탈것과 반려동물을 추가할 수 있는가.**

답은 **된다**. 근처 탭에서 주변 개체를 골라 등록하면 목록에 들어가고
소환·해제도 정상이다. 부적은 필요 없다.

이 문서는 그날 하루의 작업 전체를 정리한다. 앞선 조사 문서
(`2026-09-05-session-companion-handoff.md`)의 §7~§12 는 오진을 포함하니
그쪽을 읽을 때는 §13 과 이 문서를 먼저 볼 것.

---

## 1. 지금 쓸 수 있는 것

### 1.1 근처 탭 획득

주변 개체를 골라 동반자로 등록한다. `TrocTrHireMercenaryToTargetReq`
(ID 2338, 본문 `[u32 액터핸들][u8 플래그]`)를 게임 스레드에서 구동한다.

- 실측 등록 성공: 진돗개·집말·고양이·야생 참새·까마귀·갈매기·
  그레이트 데인·검은꼬리딱새 등.
- 집말은 이름과 능력치를 가진 탈것(에르스피아)으로 탭에 들어왔다.
- 거부되는 것도 있다. 고유 개체(로케이드 = `Animal_Black_Horse_Wild_31378`)
  와 일부 야생 개체는 코드 0xD65F8D70 으로 거절된다. 정상 동작이다.
- 되돌리려면 게임의 **반려동물 풀어주기**를 쓴다.

### 1.2 소환이 안 될 때

**게임의 소환 쿨타임이다. 모드 결함이 아니다.** 그 구간에는 어떤
개체를 넣어도 코드 `0x533C0A53` 으로 거부된다. 근처 탭에 그 사실을
띄운다.

### 1.3 인게임 표시명

목록이 내부 이름만 보여 주던 것을 고쳤다. 현지화 필드 **0x30** 이
캐릭터 표시명이다.

- 레코드 키로 먼저 찾고, 없으면 **내부 이름 끝의 `_숫자`** 로 찾는다.
  두 값이 어긋나는 행이 많다(`Animal_Parrot_Wild_32884` 는 엔티티
  32884 에 '스픽스마코 앵무새'가 있는데 레코드 키는 다른 값이다).
- 내부 이름은 지우지 않고 옆에 남긴다. 키 찾기와 야생 판별에 쓴다.
- 검색은 표시명과 내부 이름 양쪽에 걸린다.

## 2. 곁가지로 고친 것

원래 요청과 무관하지만 조사 중에 드러난 기존 결함들이다.

| 결함 | 증상 | 커밋 |
|---|---|---|
| 풀린 세션으로 구동 | 예외가 연쇄되다 메인 화면으로 튕김 | `0934f21` |
| 세션 신선도 판정이 절대 시각 | 월드 안인데 후보가 없다고 거부 | `4ed40f6` |
| 멈춘 게임을 죽은 세션으로 오판 | 창을 내리면 구동 불가 | `13aeaac` |
| 카메라 좌표 오프셋 0x18 밀림 | 프리카메라·바닥 스폰·좌표 전송이 죽은 자리를 읽음 | `b0b18fe` |
| 대기열이 영구히 막힘 | 실행 안 된 요청 하나로 이후 전부 거부 | `d9a713b` |
| 추적 재현이 게임을 죽임 | 게임 함수 직접 호출 | `55608ce` |

**카메라 오프셋은 따로 확인할 것.** `component_offset::kWorldPosition`
을 0x360 에서 0x378 로 고쳤다. 프리카메라(F9)와 바닥 스폰이 같이
되살아났을 것이나 화면으로 확인하지 않았다.

바닥 스폰은 별개로 `바닥 스폰 함수를 찾지 못했다` 경고가 뜬다. 패치로
밀린 것으로 보이며 이번에 손대지 않았다.

## 3. probe 에 넣은 명령

붙을 때마다 350MB 이미지를 다시 읽어 한 건에 2~3분이 든다. 후보가
수십 개면 그것만으로 하루가 간다.

```
heapdump <서명> [앞] [뒤]      서명이 나온 자리마다 앞뒤를 덤프
dumpmany <바이트수> <주소들>   여러 주소를 한 번에 덤프
instcount <이름조각들>         클래스별 인스턴스 개수만
```

## 4. 미완 — 전체 목록에서 추가하기

근처에 없는 종을 목록에서 골라 추가하는 것. **길은 있으나 관문이
막고 있다.**

`TrocTrSpawnCharacterCheatReq`(ID 2510)로 임의 캐릭터를 불러올 수
있다. 이 치트는 **몸통이 살아 있다** — 용병 치트 3종(고용·방출·교체)이
전부 비어 있는 것과 다르다. 본문은
`[u32 키][u32 B][float3 좌표][u8 플래그]` 이고 `spawnchar` 명령으로
건다.

구동은 성공하고 크래시도 없는데 개체가 생기지 않는다. 작업 함수
(RVA 0x2B6E530)를 읽으면 이유가 보인다.

```
call [세션vtable+0x160]   ; 스포너
call 0x1FB5B60            ; 컨텍스트 조회
cmp  byte ptr [rsp+0x68], 0
jne  진짜 작업            ; 0 이면 오류를 만들고 끝
```

**컨텍스트 버퍼의 +0x10 이 0 이면 포기한다.** 그 값이 무엇인지 아직
못 읽었다.

### 4.1 다음에 할 일

`0x1FB5B60` 에 **수동 훅**을 걸고 원본이 돌려준 버퍼의 +0x10 을 찍는다.
소환 쿨타임을 찾아낸 방식과 같다.

- 0 이면 관문이 닫힌 것이다. 무엇이 그 바이트를 세우는지 찾는다.
  개발자 모드 플래그 같은 것이면 길이 막힐 수 있다.
- 0 이 아니면 더 아래 조건이다. `B`·`플래그` 인자를 마저 훑는다.

**재현 호출은 절대 쓰지 말 것.** `trace_char_path` 가 그 방식인데
게임을 죽였다. 코드는 남아 있으나 아무도 부르지 않는다.

## 5. 폐기된 가설

전부 틀렸다. 같은 길을 다시 걷지 않기 위해 남긴다.

| 가설 | 실제 |
|---|---|
| 획득 개체는 월드 재적재가 필요하다 | 소환 쿨타임만 지나면 된다 |
| 세이브/로드가 조건이다 | 아니다 |
| 야생·조류라 소환이 안 된다 | 무관하다 |
| 한 마리 규칙이 막는다 | 자동 교체된다 |
| 2992·2962·2894 를 더 보내야 한다 | 보낼 필요 없다 |
| 힙에서 찾은 것이 용병 레코드다 | `GimmickInfo` 였다 |
| 풀린 세션이 튕김의 원인이다 | 3022 로그아웃의 결과였다 |
| 온라인이라 계정이 위험하다 | 싱글플레이다(TCP 연결 없음) |
| 용병 치트로 고용할 수 있다 | 이 빌드에서 몸통이 비어 있다 |

3022(`UnSetMainPetAndUnSpawn`)는 **쓰지 말 것.** 유효하지 않은 번호를
넣으면 작업 함수가 실패 코드를 돌려주고 클라이언트가 그것을
로그아웃으로 처리한다.

## 6. 일하는 방식에 대한 교훈

이 세션에서 가장 비쌌던 것은 기술적 난이도가 아니라 순서였다.

**하나. 사용자의 관측을 먼저 따라갈 것.**
아주 초반에 "소환된 개체 때문에 다른 개체 소환 안 됨"이라는 말이
있었다. 정답(쿨타임)에 가장 가까운 관측이었는데 흘려보내고 메시지를
두드리기 시작했다. 그 뒤로 게임을 열 번 넘게 재시작하게 만들었다.

**둘. 막히면 추측 대신 훅을 걸 것.**
후보 메시지를 하나씩 구동해 본 여러 시간은 아무것도 못 냈다. 답을
낸 것은 소환 작업 함수에 훅을 걸어 거부 코드를 찍은 30분이었다.

**셋. 힙에서 찾은 객체는 vtable 로 정체부터 확인할 것.**
번호가 들어 있다는 이유로 레코드라고 단정하고 그 위에 분석을 쌓았다.
`GimmickInfo` 였다. 확인 한 줄을 아껴서 몇 시간을 잃었다.

**넷. 하드코딩된 RVA 는 패치마다 검증할 것.**
이번에만 두 곳이 밀려 있었다(카메라 좌표, 추적 재현). 조용히 틀린
값을 쓰거나 죽는다.

**다섯. 게임 함수를 직접 부르는 진단은 만들지 말 것.**
SEH 는 우리 스레드의 접근 위반만 잡는다. 게임 함수 안에서 깨진 것은
못 되돌린다. 관측은 훅으로 한다.

## 7. 파일 지도

```
src/game/companion.{h,cpp}   획득·소환 메시지, 캡처 훅, 추적 훅, 명령 파일
src/game/roster.{h,cpp}      캐릭터·용병 표 + 표시명(현지화 0x30)
src/game/actors.{h,cpp}      살아 있는 액터 + 핸들
src/game/grant.{h,cpp}       메시지 구동, 세션 선택, 대기열
src/game/camera.{h,cpp}      좌표 오프셋(0x378), 추적 훅 설치
src/render/roster_panel.cpp  동반자/근처/탈것/용병타입/캐릭터 탭
tools/probe/main.cpp         heapdump · dumpmany · instcount
```

명령 파일은 DLL 옆의 `cdtoybox_cmd.txt` 다. 한 줄 쓰면 읽고 지운다.

```
give <키> [개수]
useitem <키> [B] [C] [D]
msg <16진 와이어>
summon <용병번호> [x y z]      2962 (미검증, 효과 없음)
spawnchar <캐릭터키> [B] [플래그]  2510 (관문에 막힘)
```
