## 원인 — 이미지 전수 스캔의 반복

`mem::Rtti::image_` 는 한 번 읽고 **안 바뀌는데**, 조회마다 처음부터 다시
훑고 있었다.

| 함수 | 하던 일 |
|---|---|
| `find_types()` | 350MB 를 **1바이트씩** (약 3.7억 회) `memcmp` |
| `find_objects()` | 이미지를 8바이트씩 훑으며 `class_of_vtable` 호출 |

한 탐색 통과에 아이템표·대응표·인벤토리·로스터·액터매니저가 줄줄이 들어
있으니 그 스캔이 대여섯 번 되풀이됐다. 그것이 2분 30초였다.

## 고친 방법 — 색인은 이미지의 순수 함수다

`call_once` 로 한 번 만들고 그 뒤로는 전부 거기서 찾는다.

- `types_` — `.?AV...@@` 타입 서술자 (이름 + 서술자 주소). 실측 **15,093개**
- `vtable_cls_` — vtable → 타입 색인. **주소 오름차순**이라 이분 탐색이 된다.
  실측 **14,351개**

`find_types` 는 목록 필터로, `find_objects` 의 사전 스캔은 색인 순회로 바뀐다.
분석 루프가 시작 직후 `build_index()` 로 비용을 앞당겨 로그에 남긴다(안 불러도
첫 조회에서 저절로 만들어진다).

`Rtti` 는 분석 스레드 지역 객체라 스레드 경합이 없다. 색인은 `mutable` +
`std::once_flag`.

## 남은 병목 — 힙 스캔 (아직 안 함)

탐색마다 **각자 11GB 힙을 한 번씩** 훑는다.

```
탐색 [아이템표]       6.3초
탐색 [아이템 대응표]  8.6초
탐색 [인벤토리]      10.8초
탐색 [로스터]        31.4초   <- 최대
탐색 [액터 매니저]   10.4초
```

**한 번의 힙 통과로 여러 vtable 을 동시에 맞추면** 더 줄일 수 있다.
`find_objects` 가 이미 그 꼴(substring 으로 모아서 한 번에 훑기)이니,
클래스마다 따로 훑는 `instances_of_class` 쪽을 그리로 모으면 된다.
